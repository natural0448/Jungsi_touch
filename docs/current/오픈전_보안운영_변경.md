이 문서는 공통 명세 service_spec.json에서 생성한다. 현재 버전은 1.9.43이며 기획·라우팅·계층 문서를 같은 변경으로 갱신한다.

2026-10-14 사용자 확정은 public.jeongsi_passes 기준 전환이며 관리자 무료 이용 예외는 추후 결정이다. 과거 명시 연결만 준비하기로 한 결정·이용권 어댑터·검수 영수증은 이력으로 보존한다. 최신 실행 변경의 규범은 이 문서와 opening_security_operations_contract이다.

## 이용권 읽기와 기본 서버 구성

실제 PostgreSQL 저장소 구성은 public.jeongsi_passes를 읽는다. revoked_at IS NULL이고 starts_at <= UTC now < ends_at인 행 중 MAX(ends_at)를 채택한다. 메타데이터/RLS/역할/필수 열과 현재 만료를 한 배치 JOIN으로 검증하고 /me의 회원 판정과 만료를 같은 요청 값에 결속한다. 트랜잭션 설정 질의는 데이터 조회와 별개다. 요청 간 이용권 캐시는 쓰지 않고 조회 장애는 기존의 안전한 이용권 오류 코드와 503으로 거절하고 SQL 세부 예외를 노출하지 않는다. 기존 이용권 표로 대체하거나 관리자를 유료로 만들지 않는다. 공개 session/v1의 3필드는 유지한다. 명시 의존 주입과 로컬 합성 저장소는 보존한다.

## 관리자 MFA·본인 상태·업무 권한

관리 요청은 Supabase Auth가 정확한 Bearer를 검증한 뒤 aal2를 신뢰한다. 같은 검증 Bearer와 publishable key로 자신의 profiles.status만 조회해 기존 RLS를 따른다. active가 아니면 403 management_account_inactive, 상태 미확인은 관리만 503 management_account_state_unverified, aal1은 403 management_mfa_required다. 기존 forecast_authorities의 편집/승인·학교 범위도 모두 필요하다. public.is_admin()이나 이메일·클라이언트 role만으로 자체 관리 권한을 부여하지 않는다. staff_roles 테이블은 가정하지 않는다. 일반·유료 학생 조회/분석에는 MFA를 추가하지 않고 관리 상태 조회 실패만으로 성공한 학생 응답을 버리지 않는다. 비직원 capabilities는 empty/false다.

## 조회·용량·보존형 정리

화면 조회는 매개변수화된 제한 범위 JOIN과 keyset을 쓴다. 전체 count·전국 FETCH와 N+1을 화면 경로에 붙이지 않는다. 제한 ID를 먼저 고른 MATERIALIZED는 별도이며 제거 자체를 성능 검증으로 간주하지 않는다. 기존 인덱스와 valid/ready·계획을 확인한 후 필요한 것만 제안한다. 시험 적재는 로컬/운영 외 DB에서 한다.

원 압축 bytes를 재압축 없이 비공개 불변 Storage에 보관하고 원격 bytes/SHA를 다시 확인한 뒤 archive pointer/resolver·현재/C 근거 보존을 검수한다. csv/support NOT NULL·길이/해시 제약이 있어 업로드만으로 본문 제거가 가능해지지 않는다. 정확 표/PK/열·해시·참조·제거 명부에 사용자가 승인한 범위만 다음 단계에서 적용한다. registry·overlays의 전량 삭제, production_allowed=false를 미사용으로 해석, 무조건 VACUUM FULL은 금지한다. 일반 VACUUM의 내부 공간 재사용과 파일 크기 축소를 구분한다. 과거 02~06 제한은 현재 강제 규칙으로 재등록하지 않는다. I/O 경고가 다시 나타나면 대량 작업을 멈추고 Owner와 재확인한다.
