# 정시터치 화면과 API 라우팅 명세

이 문서는 공통 명세 service_spec.json에서 생성한다. 현재 버전은 1.9.15이며 기획·라우팅·계층 문서를 같은 변경으로 갱신한다.

화면 URL과 서버 API 계약을 같은 요구사항에 연결한다. FastAPI 22개 경로와 업무 서비스·Supabase/Drive 어댑터를 구현했다. 코드 합성 검증과 실제 운영 연결은 구분한다. [API DTO 계약](API_DTO_계약.md)과 [백엔드 운영 준비](백엔드_운영준비.md)를 함께 읽는다.

## 권한과 응답 경계

서버가 검증한 세션·현재 이용권으로 Actor를 만든다. 요청 본문의 회원등급·학생 ID를 신뢰하지 않는다. 미인증은 401, 일반가입자의 유료 요청은 403으로 차단하고 결과·건수·상세를 반환하지 않는다. 없는 리포트와 타인 소유 리포트는 같은 404로 처리한다. 본인 분석에 확인한 성적이 없으면 409와 보류 사유다.

FastAPI는 세션 검증 후 업무 서비스를 호출하고 회원별 DTO를 적용한다. DB 이용권·본인 소유권과 자료/모형 승인 검사를 연결했다. 실제 서버·자료 연결 증거는 운영 준비 상태에서 따로 확인한다. 학부모·상담자 위임은 아직 본인 권한으로 간주하지 않는다.

## 2페이지 전체 분석 애플리케이션 계약

검증된 서버 Actor를 먼저 확인한 뒤 등록 시험과 자료 버전의 학생 성적을 기존 ExamPack으로 분석한다. 누적곡선의 부재·미승인·불일치는 전체 입력 오류가 아니라 overall.pending으로 반환하고 총점과 과목 결과를 보존한다. DEV-005는 제공된 공식 주변도수와 참고 제약을 이용해 자체 추정 공동분포·총점 곡선을 생성한다. 전체 학생 실제 DB를 필수로 요구하지 않으며 승인된 추정 모델의 overall.status는 estimated다.

서비스: jungsi_touch.application.overall_analysis.OverallAnalysisService.analyze

필수 입력: exam_id, pack_version, korean, math, inquiry. 선택 입력: english_grade, korean_history_grade.

- exam_id·pack_version은 등록 ID 토큰이며 파일 경로가 아니다
- 국어·수학은 standard_score와 선택적 choice·percentile·grade를 허용한다.
- inquiry는 서로 다른 두 과목의 subject·standard_score와 선택적 percentile·grade다.
- 점수·등급·선택과목 검증은 기존 시험 엔진에 위임
- 학생 ID·유료 플래그·자료 경로·research·승인 상태·동점 정책 입력은 거부
- percentile은 0~100 정수, grade는 1~9 정수다. bool·소수·null·알 수 없는 필드는 거절한다. 같은 시험 공식 매핑과 충돌하면 reported_percentile_conflict/reported_grade_conflict로 422다. 누적값에서 성적표 백분위를 생성하지 않는다.

학생 응답: format, exam, pack_version, score_basis, total_standard_score, subjects, absolute_grades, overall. 과목 필드: area, subject, choice, standard_score, grade, top_percent_exclusive, top_percent_inclusive, basis. 누적 필드: status, reason_code, top_percent, inclusive_top_percent, exclusive_top_percent, tie_share_percent, tie_interval_percent, tie_policy, population_id, model_version, data_kind.

누적 값은 0~100의 소수 문자열이며 내부 도수·가중치는 반환하지 않는다. include_equal; 포함/제외 값과 동점 구간도 표시. 동점 범위는 모형 신뢰구간이나 합격확률이 아님.

공급 포트: application.ports.ExamAnalysisProvider: get_exam_pack(exam_id), get_total_model(exam_id, pack_version). 총점 공급값은 서버 채택 distribution_id를 결속한 TotalModelBinding 또는 미발행 None.

응답 제외: 학생/리포트 소유자 ID; 대학 분석·환산·예측·추천; 분포 전체·도수·성별/동점 인원·가중치·정확 내부비율; 출처 로컬 경로·원문 전체·해시·연구 플래그·승인 필드.

DEV-001 계산 서비스는 stateless로 유지한다. PlatformService가 프로필/리포트 저장과 현재 권한별 DTO를 담당하고 FastAPI가 22개 경로를 등록한다. overall.analyze HTTP 응답은 jungsi.persisted-report/v1의 overall 필드에 이 계산 DTO를 포함한다. 실제 인증·DB·자료 연결 증거는 운영준비 문서의 상태를 따른다.

## 함께 생성하는 계약

화면은 apps/web/route_catalog.json을, 애플리케이션은 src/jungsi_touch/application/route_catalog.json을 사용한다. 두 파일과 이 문서는 공통 명세에서 생성하고 검사한다.

## 프레젠테이션 작업 인계

화면 담당은 별도 작업자이며 feature/presentation-foundation를 상시 사용한다. 현재 개발팀은 서버 API와 애플리케이션·데이터/인프라를 담당한다. [프레젠테이션 작업 인계](프레젠테이션_작업인계.md)에 담당·브랜치·연동 경계를 기록한다. 화면은 우리 서비스의 허용 API 결과만 이용한다. Google Drive API·폴더·토큰·전체 원자료에 직접 접근하지 않는다.

## 대학별 수능 환산 연결

[대학별 수능환산 엔진](대학별_수능환산_엔진.md)을 따른다. 구현 상태는 accepted_on_develop_synthetic_verified_live_rules_configuration_pending다. conversion.ready와 assessment.pending은 함께 존재할 수 있다. 대학 분포·입결·지원 판단·자격 미확인은 각각의 사유로 보존한다. 프레젠테이션은 독립 conversion 결과와 후속 지원 판단 상태를 표시하며 계산/조회표를 구현하지 않는다.

## 대학별 누백 연결

[대학별 누백 계산](대학별_누백_계산.md)을 따른다. 구현 상태는 implemented_synthetic_verified_live_curve_publication_pending다. conversion.ready / percentile.ready / assessment.pending은 함께 존재할 수 있다. conversion.ready / percentile.pending도 가능하며 환산 성공을 보존한다. 누백 준비만으로 지원 판단·자격·유불리를 승인하지 않는다. 프레젠테이션은 학교 환산 기준 상위 누백과 동점·자료 기준을 표시한다.

## 자체 추정분포 연결

- 판단용 구간은 별도 calibration 근거와 정책에서 생성하며 경계 [lower,upper), 비중복, 허용 category를 검증한다. 단위와 higher/lower 방향을 검사한다.

### authority_rules

- ForecastAuthorityRepository의 editor/approver와 허용 university_ids를 사용한다. 유료 등급이나 Supabase user_metadata로 관리 권한을 부여하지 않는다.
- 편집과 승인은 별도 capability이다. 정책 require_independent_approver=true이면 작성/조정자와 다른 승인자가 필요하다. false인 명시 정책과 두 capability가 있으면 개인 운영자의 승인도 가능하다. 누락 정책은 자동 false로 채택하지 않는다.
- 미허용 관리 기능은403; 조회 범위 밖 draft는 존재하지 않는 draft와 동일404이다. 클라이언트는 status/역할/작성자/승인자/검증 통과값을 지정하지 않는다.

### revision_rules

- 모든 POST는 Idempotency-Key를 요구한다. 생성 이후 expected_revision/base_result_hash/policy_version을 결속한다.
- 조정은 reason과 server-verified evidence_refs, 동일 단위의 명시 replacement를 새 revision으로 저장한다. 기본값과 이전 revision을 보존하고 조정이 재시도마다 더해지지 않는다.
- 조정은 검증/승인 승계를 해제한다. 검증/승인 hash는 정확한 채택값과 revision/자료 버전에 결속한다.
- 현재 자료/정책/카탈로그/규칙/곡선 변경과 동시 수정은409이며 미검증·미승인 값을 발행하지 않는다. 발행은 새 불변 release를 보존한다.

### DEV006 응답 소비 규칙

- DEV006②: forecast_draft.result는 최종 채택 객체, base_result는 조정 전 산출 원본이며 각각 읽기 전용이다. 수정은 허용 POST와 revision/hash/policy로 수행한다.
- adjustments의 각 항목은 target/replacement/reason/evidence_refs/actor/at/base_result_hash다. validation.receipt_hash와 approval.approval_hash는 서버가 생성한 현재 revision의 영수증이다.
- audit_events는 action/actor/at만 소비하고 직원 actor·관리 해시를 학생 화면/로그/공개 서버 데이터에 복사하지 않는다.
- 관리 draft에는context·created_at·updated_at·base_result가있으며최상위input_version은없다. result/base_result는forecast_70·acceptance_range·category_ranges이다. 공개발표본은input_version을반환한다.
- DEV006③: forecast_public.status는 published|pending이다. 학생 analysis의 forecast_release_version와 발표본 release_version 및 context/policy_version/input_version이 모두 일치할 때만 합친다.
- 학생 판정은 분석 채택 버전을 유지한다. 새 발표본/입력/규칙/곡선/카탈로그와 다르면 재분석을 요구하고 기존 분석에 새 컷만 붙이지 않는다.
- 외부 프런트는 반영 방법 code를 유리한 이유로 읽지 않고 outside/ineligible/pending을 각각 표시한다.
- API 허용 필드 또는 오류/보류 사유가 추가되면 외부 프런트 담당의 계약 수정과 별도 검증이 필요하다. 이 기획 후보 작업의 완료로 대체하지 않는다.
