# 정시터치 현재 서비스 기획

이 문서는 공통 명세 service_spec.json에서 생성한다. 현재 버전은 1.9.38이며 기획·라우팅·계층 문서를 같은 변경으로 갱신한다.

학생·학부모가 전체 성적 위치에서 출발해 유리한 대학·학과와 핵심 지원 학교를 찾는 상담 서비스다. 교사·입시담당자는 부 사용자다. 현재는 계산·권한·라우팅의 개발 기반이며 운영 서비스 완성을 의미하지 않는다.

## 화면과 회원 정책

| 페이지 | 화면 | 경로 | 회원 | 역할 |
| --- | --- | --- | --- | --- |
| 1 | 대학 발표 입시결과 | /admissions/results | 일반·유료 | 개인 성적 없이 공식 결과를 검색하고, 분리된 추정 2열은 표기·산술 조건에 따라 표시한다. |
| 2 | 내 성적 리포트 | /reports/me | 일반·유료 | 일반은 전체 성적 위치까지, 유료는 대학 분석과 선택 목록을 포함한 리포트를 이용한다. |
| 3 | 전체 대학·학과 가능성 보기 | /admissions/possibilities | 유료 | 추천 밖 모집단위까지 검색하고 개인 환산·지원 검토·유불리를 확인한다. |

1페이지의 실제 결과 조회 네 학년도는 자료 공개 범위에 따라 별도 확정한다. 2024~2027 성적 환산 비교와 결과 공개 연도를 혼동하지 않는다. 3페이지는 검색부터 상세까지 유료 전용이며 성적이 없어도 유료 검색을 허용한다. 개인 분석이 준비되지 않으면 이유와 함께 보류한다.

## 확정 요구사항

### REQ-01 공식 입시결과 조회

1페이지는 개인 성적 없이 대학·학과를 검색하고 대학 발표 지표명·결과치·단위·출처를 제공한다. 자체 누적·예상컷·개인 분석으로 미발표 값을 채우지 않는다. 추정 총 지원자·추정 탈락자 2열은 공식 값과 분리된 화면 파생값으로 유지한다. 산식·오차·실제 불합격자수와의 차이를 표시하고 동일 학년도/모집행/통계 분모·자료 결측을 검사한다. 공식 DTO·발행 자료에 추정값을 추가하지 않는다.

### REQ-02 전체 성적 리포트

국어·수학·탐구 2과목 표준점수 합과 전체 응시자 기준 추정 상위 누적을 일반·유료가입자에게 제공한다. 영어·한국사는 별도 표시하고 총점에 넣지 않는다.

### REQ-03 유료 직접 검색

3페이지의 검색·건수·목록·상세·개인 분석은 유료 전용이다. 유료 사용자는 추천·유불리·성적 입력 여부와 관계없이 서비스의 모든 모집단위를 검색한다. 분석이 없으면 모집행과 보류 사유를 표시한다.

### REQ-04 유리한 대학과 학과 찾기

4페이지는 도전학교·핵심학교·여유 후보의 기본 목록 2/3과 간호·보건·교육 와일드카드 1/3로 구성한다. 각 학교를 펼쳐 실제 학과·전형·모집군별 지원 검토 범위를 확인한다.

### REQ-05 학과별 판단 분리

학교의 1차 분류를 학과에 복사하지 않는다. 같은 학년도 수능의 개인 환산점수는 승인된 정확한 모집행 규칙으로 독립 산출한다. 전체 누적·대학 분포·지원 판단 자료가 미준비여도 환산 성공을 보존하며 지원 검토 구간·환산 유불리·지원 자격은 별도 상태로 제공한다. 학교 누백은 승인된 환산 분포로 독립 계산하고 판단 정책·입결·자격 미준비에도 성공 결과를 보존한다. 환산/누백/판단 상태와 동점 포함/제외 기준을 구분한다.

### REQ-06 연도별 성적 보정과 환산

2024~2027 비교는 현재 표준점수의 직접 대입을 하지 않는다. 전체 누적 위치와 과목별 강약을 보존하는 승인된 보정으로 해당 연도 성적을 추정한 뒤 당시 공식 대학 반영식을 적용한다.

### REQ-07 공동 성적 분포

국어·수학·탐구 2과목 성적이 있는 전체 응시자를 비교하고 문·이과로 나누지 않는다. 전체 학생의 실제 공동 성적 DB 확보를 선행 조건으로 삼지 않고, 제공된 공식 주변도수·응시 조건·참고 자료로 자체 추정 공동분포를 생성·보정·검증한다. 주변분포만으로 공동 분포를 확정하거나 같은 분위끼리 단일 매칭하지 않는다. 내부 선택과목·응시 조건을 보존하며 추정값·가정·적용 범위와 검증 버전을 명시한다.

### REQ-08 입결과 예상 기준 구분

과거 50%·70%·평균·최저 등의 정의를 보존한다. 올해 예상 70% 기준선과 지원 판단용 예상 합격권은 별도로 제공한다. 도전·핵심·여유·확인 필요 구간과 근거를 제시하며 미검증 합격확률은 제공하지 않는다.

### REQ-09 모형과 상담 판단

모형의 기본 구간에 필요한 대학·학과의 상담 판단을 적용한다. 기본 예측·이슈 근거·수동 조정·최종 채택값을 분리하고 중복 반영을 막는다. 이슈의 수치 효과는 검증 없이 고정하지 않는다.

### REQ-10 추천과 선택 집계

추천 인원과 핵심 지원 학교 선택 인원을 각각 표시한다. 학생을 중복 제거하고 대학 환산점수로 본인 집단별 순위와 동점을 처리한다. 서비스 집계를 실제 대학 지원자 수나 합격확률로 해석하지 않는다.

### REQ-11 핵심 지원 학교

관심 모집행을 핵심 지원 학교에 담고 2페이지의 유료 상담 리포트로 연결한다. 모의지원 서비스에서 확인할 내용을 제공하며 외부 자동 등록·성적 전송·계정 보관은 범위에 넣지 않는다.

### REQ-12 시험과 자료 버전

2027학년도 9월 모의평가로 시작하고 실제 수능은 별도 시험 ID와 검증 자료 버전으로 연결한다. 시험·연도·모집단·동점·산식·분포·예측 버전이 맞지 않으면 값을 보류한다.

### REQ-13 모집인원 변경

올해 모집군·최초 인원·수시 이월을 포함한 전체 변경분·공식 최종인원을 구분한다. 미공개·미확인·해당 없음·실제 0을 보존하고 미확정을 최종인원으로 표시하지 않는다.

### REQ-14 서버 권한과 소유권

Supabase 서버 검증 세션과 DB의 현재 활성 이용권으로 회원 권한을 판정한다. 본인 프로필·리포트만 허용하며 타인/없는 리포트는 같은 404다. 일반가입자에게 유료 검색 건수·상세·대학 분석·선택목록을 반환하지 않는다. 결제 사업자와 학부모·상담자 위임은 미정이다.

### REQ-15 3티어와 비공개 데이터

화면은 허용 결과를 표시하고 계산·권한 판단은 애플리케이션에서 수행한다. 원자료·환산표·전체 곡선·모델·비밀값은 데이터 계층에 둔다. DB 구조·계약·합성 예시와 실제 데이터는 구분한다.

### REQ-16 커밋과 문서 일치

개발은 Git 커밋에서 출발한다. 기능 변경은 요구사항·화면/API 경로·계층·검증을 갱신하고 같은 커밋에 포함한다. main에는 검증한 최종 코드와 그 코드에 일치하는 현재 문서를 유지한다. main은 모든 작업 완료 후 최종 문서·검증·인계가 정리된 배포 후보이며, 병합과 라이브 적용을 분리한다.

### REQ-17 원본과 범위 보존

원본·이전 버전·작업 파일을 임의로 삭제하지 않는다. 서비스 범위는 현행 AGENTS.md를 따른다. 실제 실기 반영 전형은 제외하고 비실기 예체능은 학과명만으로 제외하지 않는다.

### REQ-18 프레젠테이션 별도 담당과 브랜치

기획 정본은 시스템기획팀이 develop에서 직접 관리·배포한다. 실제 개발은 시스템·콘텐츠 담당과 프레젠테이션 담당 두 명이 각각 하나의 상시 브랜치를 재사용한다. 다른 팀은 develop의 기획을 가져가 담당 브랜치에서 구현하고 PR로 누적한다. 시스템·콘텐츠는 feature/application-pre-data-platform, 프레젠테이션은 feature/presentation-foundation을 상시 사용한다. develop의 직접 변경은 시스템기획팀의 문서와 공통 관리 범위로 제한하고 개발은 PR로만 통합한다.

### REQ-19 Google Drive 폴더 API 연동

인프라의 Drive 어댑터가 애플리케이션 소유 포트를 구현한다. 서버 고정 입력 폴더·파일 버전·SHA256·승인 명부로 읽고, 서버 고정 비공개 결과 폴더에는 새 파일을 멱등 발행한다. 실제 인증·폴더·자료 설정과 읽기/쓰기 검수는 대기다. 화면은 우리 서비스 API만 사용한다.

### REQ-20 실제 세션과 최신 분석 DTO 연결

화면 서버가 같은 Supabase 프로젝트의 SSR 쿠키에서 access token을 읽어 우리 API에 전달하고 서버 검증 신원과 현재 활성 이용권으로 session.read를 반환한다. 추정/관측, 전체 국수탐2/규칙 필수입력 비교집단, 독립 환산/누백/판정 보류를 각각 표시한다. 합성 모드는 명시적 개발/검토 설정이며 실제 연결 실패의 대체값으로 사용하지 않는다.

### REQ-21 학과별 예상 기준선과 판단 구간 생성·조정·발행

정확한 모집행별 승인된 2024~2026 비교 시계열과 정책으로 올해 예상 70%를 산출하고, 별도 보정·상담 사례 근거로 판단용 합격권과 도전/핵심/여유 구간을 산출한다. 원점수를 연도 간 직접 회귀하지 않는다. 정책·자료·검증·조정·승인·발행 버전을 보존하고 미확인 올해 이슈 영향은 null로 유지한다. 편집/승인 capability와 학교 범위를 서버 저장소에서 확인하며 유료 회원이라는 이유로 관리 권한을 주지 않는다.

### REQ-22 검증 가능한 대학·학과 추천 이유

서버가 승인 반영식의 실제 처리와 검증된 판정/발행 근거로 추천 이유를 생성한다. 총점 위치 변화와 학과 지원 판단을 구분하며 과목별 반영·선택·감점 특성은 실제 계산과 확인된 메타데이터에 한정한다. 자체 전체 국수탐2 누백에 임의 과목 가중치를 도입하지 않는다. 공개 요약에는 내부 trace·전체 규칙표·곡선·모형 가중치·담당자 식별 정보를 넣지 않는다.

### REQ-23 로컬 검증 연결과 운영 준비 분리

운영 factory를 바꾸지 않는 loopback 서버에 메모리 저장소·서버 allowlist 시험사용자·수신PC에서 보호한 승인자료를 주입한다. 신뢰명부/영수증/버전을검증하고실제DB/운영인증/모형승인/외부화면인수는별도기록한다.

### REQ-24 외부 전달물과 응답의 내부자료 노출 차단

정상·오류·보류·멱등 재응답·리포트·발표본과 브라우저 전달물에 역할별 재귀 허용목록을 적용한다. 원자료·전체 환산표·곡선·모델·비밀값은 서버 전용이며 학생의 허용 점수·근거·공식 출처와 직원용 관리 DTO는 보존한다.

### REQ-25 화면 우회와 분석 API 직접 접근 통제

운영 분석 API는 인증된 서버 중계를 통해 접근하며 서버 간 신원과 실제 사용자 세션·현재 이용권·소유권·관리 학교 범위를 각각 검증한다. body/role/paid/Origin/CORS나 임의 사용자 헤더로 권한을 부여하지 않는다. 미구현 서버 중계를 운영 완료로 표시하지 않는다.

### REQ-26 계정별 반복 분석과 대량 결과 수집 통제

무료 전체 누백과 유료 환산·추천·조회에 요청량·동시성·새 성적·계산 비용·반환량 예산을 적용한다. 계정·시험 기준의 공유 저장소에서 계산 전 원자적으로 판정하며 새 JWT/요청키/프로필/리포트·페이지 순회·서버 재시작으로 초기화하지 않는다. 정상 대학·학과 검색 범위와 성공 결과 보존 원칙은 유지한다.

## Google Drive 폴더 API 연동

Google Drive API 고정 폴더·파일 버전/해시·승인 읽기와 별도 결과 폴더 멱등 새 파일 쓰기 어댑터를 구현했다. 실제 계정·폴더·승인 자료·토큰 갱신·읽기/쓰기 검증은 설정 대기다.

프레젠테이션 → 우리 서비스 API → 애플리케이션 포트 ← Drive API 어댑터 → 비공개 Google Drive 폴더

애플리케이션은 자신이 정의한 포트에 의존한다. Drive API 호출·파일 변환·인증·재시도는 인프라 어댑터가 담당하며 전체 원자료와 인증값을 학생 응답에 넣지 않는다.

화면은 우리 서비스의 허용 API 결과만 이용한다. Google Drive API·폴더·토큰·전체 원자료에 직접 접근하지 않는다.

### 읽기와 쓰기

서버에 설정한 입력 폴더와 발행 버전만 읽는다. 파일 식별자·자료 버전·내용 해시·학년도/시험·출처·검수 상태를 연결하며 단순 최신 수정 파일을 승인 데이터로 자동 채택하지 않는다.

서버에 설정한 결과 폴더로 새 산출 파일 또는 새 버전을 기록한다. 원본·이전 버전은 보존하고 삭제·휴지통 이동·동기화 정리는 수행하지 않는다. 사용자 성적과 공개 산출물의 접근 범위를 구분한다.

실제 폴더 ID·인증 계정·키/토큰·자료·입결·곡선·모델·검수 결과는 Git 제외 설정/폴더 또는 비공개 저장소에 둔다. 코드에는 어댑터와 자료 형식 계약만 둔다.

파일·버전·권한·검수 상태가 준비되지 않으면 데이터 대기 또는 오류 사유를 반환한다. 다른 시험·연도·미승인 모형으로 대체하지 않는다.

### 남은 설정

- 실제 입출력 폴더·서버 계정 권한·OAuth와 갱신 설정
- 비공개 발행 명부/승인 자료 값과 형식 호환 검수

### input_rules

- 조정은 검증/승인 승계를 해제한다. 검증/승인 hash는 정확한 채택값과 revision/자료 버전에 결속한다.

### DEV006 응답 소비 규칙

- DEV006②: forecast_draft.result는 최종 채택 객체, base_result는 조정 전 산출 원본이며 각각 읽기 전용이다. 수정은 허용 POST와 revision/hash/policy로 수행한다.
- adjustments의 각 항목은 target/replacement/reason/evidence_refs/actor/at/base_result_hash다. validation.receipt_hash와 approval.approval_hash는 서버가 생성한 현재 revision의 영수증이다.
- audit_events는 action/actor/at만 소비하고 직원 actor·관리 해시를 학생 화면/로그/공개 서버 데이터에 복사하지 않는다.
- 관리 draft에는context·created_at·updated_at·base_result가있으며최상위input_version은없다. result/base_result는forecast_70·acceptance_range·category_ranges이다. 공개발표본은input_version을반환한다.
