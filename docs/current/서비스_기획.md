# 정시터치 현재 서비스 기획

이 문서는 공통 명세 service_spec.json에서 생성한다. 현재 버전은 1.2.3이며 기획·라우팅·계층 문서를 같은 변경으로 갱신한다.

학생·학부모가 전체 성적 위치에서 출발해 유리한 대학·학과와 핵심 지원 학교를 찾는 상담 서비스다. 교사·입시담당자는 부 사용자다. 현재는 계산·권한·라우팅의 개발 기반이며 운영 서비스 완성을 의미하지 않는다.

## 확정 요구사항

### REQ-01 공식 입시결과 조회

1페이지는 개인 성적 없이 대학·학과를 검색하고 대학 발표 지표명·결과치·단위·출처를 제공한다. 자체 누적·예상컷·개인 분석으로 미발표 값을 채우지 않는다.

### REQ-02 전체 성적 리포트

국어·수학·탐구 2과목 표준점수 합과 전체 응시자 기준 추정 상위 누적을 일반·유료가입자에게 제공한다. 영어·한국사는 별도 표시하고 총점에 넣지 않는다.

### REQ-03 유료 직접 검색

3페이지의 검색·건수·목록·상세·개인 분석은 유료 전용이다. 유료 사용자는 추천·유불리·성적 입력 여부와 관계없이 서비스의 모든 모집단위를 검색한다. 분석이 없으면 모집행과 보류 사유를 표시한다.

### REQ-04 유리한 대학과 학과 찾기

4페이지는 도전학교·핵심학교·여유 후보의 기본 목록 2/3과 간호·보건·교육 와일드카드 1/3로 구성한다. 각 학교를 펼쳐 실제 학과·전형·모집군별 지원 검토 범위를 확인한다.

### REQ-05 학과별 판단 분리

학교의 1차 분류를 학과에 복사하지 않는다. 개인 환산점수·지원 검토 구간·환산 유불리를 각각 산출하고 비교 근거와 자료 상태를 제공한다.

### REQ-06 연도별 성적 보정과 환산

2024~2027 비교는 현재 표준점수의 직접 대입을 하지 않는다. 전체 누적 위치와 과목별 강약을 보존하는 승인된 보정으로 해당 연도 성적을 추정한 뒤 당시 공식 대학 반영식을 적용한다.

### REQ-07 공동 성적 분포

국어·수학·탐구 2과목 성적이 있는 전체 응시자를 비교하고 문·이과로 나누지 않는다. 과목별 주변분포만으로 공동 분포를 확정하거나 같은 분위끼리 단일 매칭하지 않는다.

### REQ-08 입결과 예상 기준 구분

과거 50%·70%·평균·최저 등의 정의를 보존한다. 올해 예상 70% 기준선과 지원 판단용 예상 합격권은 별도로 제공한다. 도전·핵심·여유·확인 필요 구간과 근거를 제시하며 미검증 합격확률은 제공하지 않는다.

### REQ-09 모형과 상담 판단

모형의 기본 구간에 필요한 대학·학과의 상담 판단을 적용한다. 기본 예측·이슈 근거·수동 조정·최종 채택값을 분리하고 중복 반영을 막는다. 이슈의 수치 효과는 검증 없이 고정하지 않는다.

### REQ-10 추천과 선택 집계

추천 인원과 핵심 지원 학교 선택 인원을 각각 표시한다. 학생을 중복 제거하고 대학 환산점수로 본인 집단별 순위와 동점을 처리한다. 서비스 집계를 실제 대학 지원자 수나 합격확률로 해석하지 않는다.

### REQ-11 핵심 지원 학교

관심 모집행을 핵심 지원 학교에 담고 2페이지의 유료 상담 리포트로 연결한다. 모의지원 서비스에서 확인할 내용을 제공하며 외부 자동 등록·성적 전송·계정 보관은 범위에 넣지 않는다.

### REQ-12 시험과 자료 버전

2027학년도 9월 모의평가로 시작하고 실제 수능은 별도 시험 ID와 검증 자료 버전으로 연결한다. 시험·연도·모집단·동점·산식·분포·예측 버전이 맞지 않으면 값을 보류한다.

### REQ-13 모집인원 변경

올해 모집군·최초 인원·수시 이월을 포함한 전체 변경분·공식 최종인원을 구분한다. 미공개·미확인·해당 없음·실제 0을 보존하고 미확정을 최종인원으로 표시하지 않는다.

### REQ-14 서버 권한과 소유권

Supabase 서버 검증 세션과 DB의 현재 활성 이용권으로 회원 권한을 판정한다. 본인 프로필·리포트만 허용하며 타인/없는 리포트는 같은 404다. 일반가입자에게 유료 검색 건수·상세·대학 분석·선택목록을 반환하지 않는다. 결제 사업자와 학부모·상담자 위임은 미정이다.

### REQ-15 3티어와 비공개 데이터

화면은 허용 결과를 표시하고 계산·권한 판단은 애플리케이션에서 수행한다. 원자료·환산표·전체 곡선·모델·비밀값은 데이터 계층에 둔다. DB 구조·계약·합성 예시와 실제 데이터는 구분한다.

### REQ-16 커밋과 문서 일치

개발은 Git 커밋에서 출발한다. 기능 변경은 요구사항·화면/API 경로·계층·검증을 갱신하고 같은 커밋에 포함한다. main에는 검증한 최종 코드와 그 코드에 일치하는 현재 문서를 유지한다.

### REQ-17 원본과 범위 보존

원본·이전 버전·작업 파일을 임의로 삭제하지 않는다. 서비스 범위는 현행 AGENTS.md를 따른다. 실제 실기 반영 전형은 제외하고 비실기 예체능은 학과명만으로 제외하지 않는다.

### REQ-18 프레젠테이션 별도 담당과 브랜치

프레젠테이션 구현은 별도 작업자가 맡는다. 현재 개발팀은 애플리케이션·데이터/인프라와 서버 API를 담당한다. 시스템기획팀은 develop에서 검증한 기획 정본문서를 관리·공유한다. 두 개발 담당은 origin/develop의 확정 기획을 가져가 서로 다른 feature 브랜치에서 구현하고 공통 명세 변경을 조율한다.

### REQ-19 Google Drive 폴더 API 연동

인프라의 Drive 어댑터가 애플리케이션 소유 포트를 구현한다. 서버 고정 입력 폴더·파일 버전·SHA256·승인 명부로 읽고, 서버 고정 비공개 결과 폴더에는 새 파일을 멱등 발행한다. 실제 인증·폴더·자료 설정과 읽기/쓰기 검수는 대기다. 화면은 우리 서비스 API만 사용한다.

Git 변경 범위와 해당 계약·필수 커밋 검산을 확인한다. 원자료 전수검수나 전국 재집계를 매 개발 작업에서 반복하지 않는다.

## Google Drive 폴더 API 연동

Google Drive API 고정 폴더·파일 버전/해시·승인 읽기와 별도 결과 폴더 멱등 새 파일 쓰기 어댑터를 구현했다. 실제 계정·폴더·승인 자료·토큰 갱신·읽기/쓰기 검증은 설정 대기다.

프레젠테이션 → 우리 서비스 API → 애플리케이션 포트 ← Drive API 어댑터 → 비공개 Google Drive 폴더

애플리케이션은 자신이 정의한 포트에 의존한다. Drive API 호출·파일 변환·인증·재시도는 인프라 어댑터가 담당하며 전체 원자료와 인증값을 학생 응답에 넣지 않는다.

화면은 우리 서비스의 허용 API 결과만 이용한다. Google Drive API·폴더·토큰·전체 원자료에 직접 접근하지 않는다.

### 읽기와 쓰기

서버에 설정한 입력 폴더와 발행 버전만 읽는다. 파일 식별자·자료 버전·내용 해시·학년도/시험·출처·검수 상태를 연결하며 단순 최신 수정 파일을 승인 데이터로 자동 채택하지 않는다.

서버에 설정한 결과 폴더로 새 산출 파일 또는 새 버전을 기록한다. 원본·이전 버전은 보존하고 삭제·휴지통 이동·동기화 정리는 수행하지 않는다. 사용자 성적과 공개 산출물의 접근 범위를 구분한다.

실제 폴더 ID·인증 계정·키/토큰·자료·입결·곡선·모델·검수 결과는 Git 제외 설정/폴더 또는 비공개 저장소에 둔다. 코드에는 어댑터와 자료 형식 계약만 둔다.

파일·버전·권한·검수 상태가 준비되지 않으면 데이터 대기 또는 오류 사유를 반환한다. 다른 시험·연도·미승인 모형으로 대체하지 않는다.
