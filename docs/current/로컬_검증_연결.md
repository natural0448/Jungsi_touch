# 로컬 검증 연결

이 문서는 공통 명세 service_spec.json에서 생성한다. 현재 버전은 1.9.48이며 기획·라우팅·계층 문서를 같은 변경으로 갱신한다.

현재 상태: implemented_local_only_synthetic_native_verified_actual_data_hold; local_code_scoped_native_and_confirmed_429_hooks_CI_PR14_develop91_verified_actual_data_hold.

받는 Windows PC에서 별도 로컬 서버로 승인 자료의 화면·권한·보류 흐름을 검수한다. 운영 배포·DB 검증·모형 승인과 분리한다.

확인한 출발 develop: 354d45097a501d788b8bb93ef238a15aef4d3ae3. 요청 2판 SHA256: c6258a8e38a949ae1476c054b24b7b9a7bc4a6bdb7dd441e4dcdd494f0f7d4e0. 이후 후보의 미래 SHA/미실행 검증 완료는 기록하지 않는다.

## 시험 사용자와 독립 승인

일반·유료·편집자·승인자는 서로 다른 네 subject다. 회원 종류와 직원 capability는 별개다.

명시적인 issue 명령이 서로 다른 네 subject와무작위opaque token의서버exact allowlist를생성한다. UTC issued_at<=now<expires_at·최대8시간이며만료·미등록·잘못된역할을거절한다. 실제 token/subject는DPAPI보호비공개설정으로만전달하고공개문서/Git/로그/브라우저빌드에넣지않는다.

editor/approver와 유료 이용권은 독립이다. 세 회원 종류를 네 시험 subject로 구성해 편집자와 독립 승인자를 분리한다. 실제 학교 허용 목록이 없으면 빈 범위를 유지하며 실제 발행 양성 검수는 NOT_RUN이다.

require_independent_approver=true 정책을 완화하지 않는다. 편집 기여자의 자기 승인403과 별도 승인자 subject를 검수한다. 승인 입력·정책·학교 범위가 없으면 capability 확인까지만 하며 실제 컷 발행/모형 승인으로 확대하지 않는다.

소유권·active=true 이용권 UTC 기간·허용 학교·만료·미등록 token 거부를 유지한다. 실제 학교 허용 목록이 없으면 빈 범위다. SYNTHETIC 회귀는 실제 학교 발행 양성 검수의 증거가 아니다.

## 자료 발행 권한과 신뢰 기준

공개 자료 정리와 시험팩 확인은 엔진 승인이 아니다. engine_approved=false/production_allowed=false를 approved로 덮지 않는다. 명시된 engine_approved는 정확 bool이어야 하며 false는 계산 승인으로 해석하지 않고 null/0/문자열은 거절한다. 부재만으로 승인하지 않으며 별도 명부와 승인 증거가 필요하다.

관리자가 따로 확인한 신뢰 명부/선택명부 SHA를 받는 파일과 독립 결속한다. 공급 파일 스스로 계산한 해시나 status 문자열만으로 승인하지 않는다.

권한있는 데이터팀의 승인 발행 명부가 없으면 목록·시험팩 준비의 부분 검수다. 대학 곡선·지원 판단·예상 기준은 기존 pending·503/null이다. 승인 entry가 없는 명부로 ready 숫자를 만들지 않는다.

이 목록은 기존 provider kind의 참고 예시이며 완전한 허용/금지 목록이 아니다. DriveDataProvider와DriveForecastInputProvider가등록된kind/key를기존포트/승인/context검사로읽는다. 새kind를목록에추가했다는이유로승인하지않고예시4kind밖이라고기존입력을일괄차단하지않는다.

참고 kind 예시: exam_pack, total_model, catalog, analysis, conversion, percentile, estimate_receipt, forecast_inputs, forecast_policy, forecast_context

데이터팀의 시험팩·승인 entry가 없는 명부·후보/HOLD 검수 묶음을 수령했다. 자료 묶음과 해시 준비 완료는 곡선/규칙/모형 승인이나 실제 기대값 정확도 인수가 아니다. 인원 집계의 원문 범주 정의는 데이터팀이 설명·대조했고 이 QA 확인을 운영 승인으로 확대하지 않는다.

## Drive와 로컬 파일의 출처

Drive 다운로드는 승인 명부·file_id·parents/input_folder·drive_version·평문SHA/bytes·다운로드 시각/검수자/출처 영수증에 결속한다. 캐시 재읽기도 별도로 pinned한 명부/선택명부·영수증 SHA와 출처·폴더/판·평문SHA/bytes를 재검증한다. offline 캐시는 고정 스냅샷이다. local_filesystem을 실제 Drive GET/다운로드 증거로 기록하지 않는다.

| 출처 | 필요한 고정 근거 |
| --- | --- |
| drive_download | registry_sha256, file_id, parents, input_folder, drive_version, plaintext_sha256, plaintext_bytes, downloaded_at, reviewer, source_receipt_sha256 |
| local_filesystem | selection_sha256, local_artifact_id, local_version, payload_version, plaintext_sha256, plaintext_bytes, captured_at, reviewer, source_receipt_sha256 |

메모리 jungsi.data-registry/v1 entry에 transport=local_filesystem과 local_artifact_id/local_version을 명시한다. kind/key/sha256/version/status는 기존 DriveDataProvider init/load의 승인·payload version 검사에 재사용한다. 실제 file_id/drive_version/Google parents를 가공하거나 alias로 위장하지 않는다. 운영 DriveClient는 불변이다.

실제 Drive pin이 없으면 권한 있는 데이터팀의 별도 local selection을 독립 신뢰 SHA로 고정한다. path와 원본은 비공개이며 local client가 평문 SHA/bytes와 pinned receipt를 확인한다. 파일 이름이나 최신 시각으로 source를 자동 승인하지 않는다.

로컬 선택명부 형식은 jungsi.local-selection/v1이며 transport=local_filesystem이다. 항목은 kind, key, local_artifact_id, local_version, sha256, bytes, payload_version, status, source_timezone, path, engine_approved (optional exact bool), approval_evidence, approval_evidence_sha256다. 별도 승인 문서 jungsi.local-data-approval/v1은 status=approved, scope=local_verification과 local_artifact_id/local_version/sha256/payload_version의 정확한 조합에 결속한다. 이 승인은 운영 production 승인이나 모형 adopt/register가 아니다. path·영수증·승인 명부의 실제 값은 모두 비공개다.

## 수신 PC에서 DPAPI 보호

DPAPI 기본 사용자 범위로 받는 PC·사용자가 자기 환경에서 새로 보호하고 RAM 복호화한다. 발신PC 암호문 전달을 수신자 복호화 방법으로 삼지 않는다. LOCAL_MACHINE flag와 공용 키 공유를 금지한다. roaming profile 예외가 있어 절대적인 다른 PC 복호화 불가를 약속하지 않는다. MAC 보호 내용에 명부/영수증 metadata를 결속하고 평문SHA를 확인한다. 기존 원본은 보존하며 신규 평문 파일·debug/crash payload·키 출력은 금지한다.

RAM만 복호화하는 설계와 일부 native buffer zeroing은 Python 모든 객체의 완전 메모리 제거를 보장하지 않는다. 이번 검수 PC의 동일 Windows 사용자에서 DPAPI roundtrip과 local HTTP/HOLD 검수는 PASS다. 외부 수신 PC 재현과 다른 PC/계정의 실제 복호화 거부는 별도 NOT_RUN이다.

이번 선택은 DPAPI다. AES-GCM·키 별도 전달·nonce 재사용 금지·metadata AAD·InvalidTag 거부·dependency lock 변경은 별도 범위 검토 없이 도입하지 않는다.

[Microsoft DPAPI 설명](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)에 따른 기본 사용자 범위를 사용한다. 암호 해제 성공만으로 자료를 approved로 취급하지 않는다.

## 계산 성공과 보류

요청 시험팩 엔트리가 없거나 MissingDataProvider가 None을 반환하면 overall.analyze는 exam_not_available/HTTP503이다. 엔트리가 등록됐지만 미채택이면 provider의 artifact_not_approved/503을 overall이 exam_data_unavailable/HTTP503으로 변환한다. 승인·유효 시험팩 계산 성공 후 모형 없음/미승인에서만 total_standard_score/subjects를 보존하고 total_model_missing/total_model_not_approved pending/null을 구분한다. approved_count=0만으로 두503 중 하나를 결정하지 않는다. 대학 규칙/곡선/컷 부족은 해당 산출만 보류한다.

실제9월 2~3건은 승인 시험팩/곡선/규칙과 독립 기대영수증에 결속한다. 시험팩 미등록·등록미채택·승인시험팩/모형부족을 각각 검수한다. 현재 구분은 e764 고정 소스 판독이고 기존 native는 catalog/권한/host 범위여서 overall 두503 직접 HTTP 관측은 NOT_RUN이다.

## 외부 화면의 실제 연결

PR6 Supabase SSR 쿠키 경로는 localhost에서 운영 사이트 쿠키나 local fixed 사용자 token을 자동으로 받지 못한다. 서버 전용 로컬 Caller와 private 토큰 전달은 외부 담당의 후속이다. backend 시험 인증 준비만으로 화면 실연동을 완료 처리하지 않는다.

publishable 설정 준비와 실제 localhost 로그인/쿠키/JWT·Caller 검수를 구분한다. 값·비공개 설정 파일 경로를 공개 정본에 복사하지 않는다.

API 22개·DTO nullable·권한·Idempotency·보류 코드는 불변이다. 발표 근거는 유효한 release/policy/input 세 버전과 공개 context17필드의 정확한 동일성으로 결합한다. PR6 소스/CI 관측은 실제 localhost Caller·브라우저 인수가 아니다.

서비스 네 모듈·test와 공통23파일은 구현429482ec6a3e0be7ac5d25512fcf902580a04c73의 같은 커밋으로 결속됐다. 정상 pre-commit/pre-push의561건·정확 구현 HEAD CI 두 건과 PR14 merged·develop91eb0c5a1f67115d64227f71b87f6dd8ec66085a의 동일 tree/정확 CI success를 확인했다. 기존 고정 runtime의 CLI 도움말 네 개 exit0·검수PC의 local native 증거를 보존한다. 아래 명령은 확정 소스의 실행 형식이며 각 명령 직접 실행·외부 수신PC/브라우저·실제 승인 수치 검수와 구분한다. ## 담당과 인수 순서

| 담당 | 작업 |
| --- | --- |
| planning | 공통 명세·생성 가이드·정합성 검사 |
| service | 별도local factory/저장소/시험session/암호source·합성/native검사 |
| data | 정본·독립 승인 발행명부·신뢰SHA·실제 기대값 |
| frontend | 서버 전용local Caller·브라우저1~4페이지와관리화면인수 |

실제 자료·명부 값·token·키·학생 성적·곡선·환산표·.env는 비공개 위치에 둔다. .env 예시도 Git 제외이며 공개 소스와 합성 회귀에 실제 값을 복사하지 않는다.

1. 데이터팀의 승인 범위·명부/선택명부·신뢰 SHA·독립 출처 영수증을 먼저 확인한다.
2. 받는 PC에서 새 DPAPI 캐시에 보호하고, 재읽기의 버전·출처·SHA 거부를 검증한다.
3. 별도 loopback 서버와 네 시험 subject를 준비하며 메모리 소실/운영 NOT_RUN을 확인한다.
4. 외부 화면 담당이 서버 전용 Caller를 연결하고 승인된 기대값·보류 사유로 화면을 검수한다.
5. 정확한 소스·명령·검수 범위·영수증을 남기고 운영 DB/인증/배포 완료와 구분한다.
