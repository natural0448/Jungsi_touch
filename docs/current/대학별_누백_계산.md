# 대학별 환산 누백 계산

이 문서는 공통 명세 service_spec.json에서 생성한다. 현재 버전은 1.9.176이며 기획·라우팅·계층 문서를 같은 변경으로 갱신한다.

상태: implemented_synthetic_verified_live_curve_publication_pending. 작업 항목: [DEV-004](../work_items/DEV-004-university-percentile.json). 대학 환산점수와 누백·지원 판단은 애플리케이션에서 각각 계산한다. 프레젠테이션은 허용 DTO의 상태·수치·기준만 표시하며 인프라는 애플리케이션 소유 포트의 승인 자료를 공급한다.

서비스: jungsi_touch.application.university_percentile.UniversityPercentileService.calculate. API: POST /api/v1/reports/{report_id}/university-results; POST /api/v1/reports/{report_id}/candidates; GET /api/v1/reports/{report_id}. 유료·본인 리포트·확인 성적·현재 revision·멱등을 기존 서버 정책으로 먼저 검증한다. 일반회원 재조회·재시도 DTO에는 percentile을 포함한 대학 분석 전체를 제외한다.

## 누백의 정의

같은 시험·학년도·비교 모집단 전체에 동일 대학 환산식과 가산점 처리를 적용한 점수 분포에서 본인의 정확한 환산점수 이상인 도수/가중치 비율 ×100이다. 동점 포함 상위 누적을 기본값으로 표시하며 관측 인원과 모형 가중치를 구분한다.

## 계산과 독립 상태

- 동점 포함 top_percent = inclusive_top_percent = (본인보다 높은 도수/가중치 + 동점 도수/가중치) / 전체 도수/가중치 ×100, exclusive_top_percent = 더 높은 도수/가중치 / 전체 ×100, tie_share_percent = 포함 - 제외다.
- Fraction 정확값으로 학교 환산점수와 누적 도수/가중치를 계산한다. 표시된 converted_score나 반올림 문자열을 누백 입력으로 사용하지 않는다. 최종 백분율만 기존 소수 문자열 표시 계약을 따른다.
- 학교라도 캠퍼스·모집단위·전형·군·규칙/가산점 범위가 다르면 별도 결속한다. 대학명 또는 학과명 유사성으로 곡선을 자동 공유하지 않는다.
- 동일 학년도 actual_exam 환산과 승인된 명시적 mock_compatibility의 mock_exam 환산만 독립 포트의 정확한 시험 곡선에 조회한다. 실제 수능 곡선을 모평에 임의 적용하지 않는다.
- 2024~2027 과거 비교는 기존 승인 연도 보정과 당시 환산·분포 계약을 유지한다. 현재 누백을 다른 연도 years에 복사하지 않는다. 기존 승인된 보정 경로의 converted_percentile 호환과 score_basis를 보존한다.
- 유효한 환산점수가 관측 분포의 최소보다 낮으면 포함/제외 100%, 최대보다 높으면 0%, 동점 비중 0%가 가능하다. 분포의 관측 최대를 공식 점수 상한으로 추정하지 않는다. 기존 입결 발표점수의 원문 범위 검증은 별도로 유지한다.
- 자료가 없거나 미승인·불완전·모집단 미검증·결속 오류이면 pending/null과 사유를 반환한다. 실제 0%/100%는 준비된 숫자 문자열이며 대기 값과 구분한다.
- 본인 환산점수·승인 곡선이 준비되면 전체 총점 모형·지원 판단 정책·입결·예상선·비성적 자격 자료가 없어도 누백을 제공한다. 후속 분석 오류가 환산점수와 누백 상태를 지우지 않는다.
- 불변 PercentileResult의 Fraction 포함·제외 누적을 각각 계산하고 동점 비중은 정확값의 차이를 표시한다. 표시 문자열의 차이로 동점 비중을 만들지 않는다. dto()는 매번 새 허용 키 객체다.
- 현재 판단 정책은 독립 누백의 정확 곡선 context/version에 결속한다. analysis에 곡선을 중복 저장할 필요는 없으며 다른 curve_version의 정책은 보류한다.
- 학교 곡선이 필요한 성적 보유 집단으로 한정되면 전체 총점과 모집단이 달라진다. 범위를 표시한 독립 학교 누백은 제공할 수 있으나 같은 모집단을 요구하는 환산 유불리·지원 판단 승인을 자동으로 부여하지 않는다.

## 시험·규칙·모집행·모집단 결속

- 발행 봉투의 version/status/release_id/academic_year/exam_id/source_pack_version/exam_type/rule_version과 곡선의 학년도·시험·rule_id/rule_version·score_scope·score_metric·score_scale_id·bonus_treatment를 정확한 환산 결과와 결속한다.
- binding은 offering_pk,academic_year,university_id,campus,department,track,group,rule_version,curve_version을 확인한다. 일치 binding은 정확히 하나여야 하며 중복·다른 모집행/규칙으로 대체하지 않는다.
- 곡선 metadata의 status=approved,rule_review_status=calculation_verified,complete=true,population_verified=true 및 출처·도수 합=expected_total_weight를 확인한다. kind=observed_counts/estimated_weights와 population_id/source_model_id/source_model_version을 보존한다.
- 신규 독립 누백은 사전 승인된 전체 비교 모집단을 사용한다. 서비스 이용자·지원자 일부·최종 등록자 분포를 전국 전체 수험생 분포로 표시하지 않는다.
- 학교 환산 분포는 승인한 공동 성적 도수 또는 검증된 공동분포 모형·대학별 기존 환산곡선으로 발행한다. 입결 컷 몇 개·과목별 주변분포·성적표 백분위만으로 새 학교 전체 누백을 만들지 않는다.
- 기존 research/reviewed/source_verified/internal_review_only 자료를 구조 검사나 저장 형식 검증만으로 approved로 바꾸지 않는다. 실제 자료 부족과 코드 구현 완료는 별도로 기록한다.
- 사용자 제공 공식 주변분포·기존 참고곡선/표본을 이용한 자체 추정 공동분포와 환산곡선 제작을 이어간다. 보정·holdout·민감도와 검증 범위를 갖춘 estimated_weights로 발행하며 추정 가중치를 실제 전국 도수라고 표시하지 않는다.
- 기본 전체 집단 외에는 신규 봉투의 승인된 comparison_population만 허용한다. 실제 규칙 필수 입력·학년도/시험/pack/rule/curve/population/검증 영수증 버전을 결속하고 오류 시 누백만 pending이다. 레거시 보정 성공은 기존 전체 집단 계약을 유지한다.
- 기본 전체/레거시는 whole_complete를 유지한다. required_rule_inputs_present는 비교집단 계약·별도 고정 영수증을 함께 검증한 새 독립 릴리스만 허용한다. 모집단이 다른 총점/학교 누백의 advantage는 기존 동일 모집단 검사에 따라 보류한다.
- 참고 환산·참고 누백은 시험/학년도·모형·산식/버전·점수축·모집행 기본 PK·동점·분모 및 자료판을 함께 검증한다. 과거 입결 기준값, 학생별 참고 누백과 정식 지원 판정은 다른 값이다.

## 화면 표시와 담당

- 대학 분석 카드·상세·리포트에 대학 환산점수 / 대학 환산 기준 상위 누백 / 지원 판단을 각각 표시한다. 누백이 낮을수록 같은 비교 모집단 내 앞쪽임을 설명한다.
- top_percent,동점 포함/제외 구간,자료 기준·학년도·시험과 data_kind를 표시한다. 전체 표준점수 누백·학교 누백·성적표 백분위를 혼용하지 않는다.
- 누백 0%를 빈 값으로 숨기지 않고 ready 상태와 함께 표시한다. pending은 사유와 대기를 표시한다. 개인점수·누백의 가상 사례는 실제 대학 자료와 분리한다.
- 같은 모집단/시험/학년도/동점 처리와 승인 총점 기준이 확보돼야 전체 누백과 대학 누백의 차이로 유불리를 표시한다. 준비되지 않으면 유불리만 대기한다.
- 로컬 기획 미리보기는 ignored outputs에서 최신 develop의 실제 애플리케이션 가상 응답을 이용한다. 운영 apps/web 구현은 feature/presentation-foundation의 별도 화면 담당 소유다.
- population_scope=whole_complete는 전체 국수탐2, required_rule_inputs_present는 대학 반영에 필요한 성적을 모두 보유한 명시적 비교집단이다. 두 범위를 구분해 표시하고 분모가 다르면 전체 누백과 차이를 유불리로 제시하지 않는다.
- 진행 중인 3페이지 참고 환산/누백과 4페이지 참고 후보는 정식 환산·합격 판단과 분리해 참고 추정으로 표시한다. 근거 없는 합격 확률이나 여유·핵심·도전·와일드카드 판정은 만들지 않는다.

## 검증과 인수

- 승인된 정확한 환산점수/곡선만으로 conversion.ready + percentile.ready + assessment.pending이 반환된다. 전체 모형/입결/예상선/판단/자격 부재·오류 격리를 API까지 검수한다.
- 동점 포함·제외·모두 동점·표시값과 내부 Fraction 차이·관측 최소/최대·분포 밖 유효 점수의 0%/100%를 독립 손계산 합성값과 대조한다.
- 학교/캠퍼스/학과/전형/군/시험/학년도/pack/rule/curve/population 결속·중복 binding·미승인/미검증/불완전 자료·가중치 합 및 숫자 형식을 거부한다.
- 일반/타인/미확인 프로필·revision·멱등·재조회에서 누백과 내부 자료를 누출하지 않는다. mutable 반환 객체가 원본 곡선·규칙·결과를 수정하지 않는다.
- 기존 승인 연도 보정·환산·입결·후보·통계·상담 출력 합성 회귀와 문서/계층/참조/제외/브랜치/Git 스냅샷 CI를 통과한 PR만 develop에 통합한다.
- 로컬 예시의 ready/분포대기/미승인/성적입력전·일반/유료·모바일 화면에서 학교 누백 수치와 각 상태를 확인한다.
- 실제 데이터 readiness는 기존 정본/검산 근거를 재사용해 별도 기록한다. 전국 학교 승인 또는 실서버 연결을 합성 구현 완료로 주장하지 않는다.
- 전체/필수입력보유 집단 구분·missing 영어 비치환·승인 없는 subset 거절·규칙과 필터 불일치·제외 가중치/집계 범위·모집단 차이에서 유불리 보류를 검수한다.
- Deno v2 정수 유리수 점수의 정확 정렬·동점 포함/제외·범위·native bigint·잘못된 분모/혼합 표현·중복 bin을 검수한다. NativeDataProvider preflight→환산→독립 누백 경로와 공개 DTO의 내부 분수 비노출을 함께 검사하며 미승인 v2는 성공 환산을 보존하고 누백만 보류한다.
- 조건부 내부 방법 조회는 native 학년도/검증 범위/미모델·결측·타입/중복·head 변경/HOLD, SECURITY INVOKER/search_path 및 PUBLIC/anon/authenticated 직접 거부를 독립 검수한다. 운영 app-role 실행·엔진 연결은 로컬 합성과 구분한다.
- 조건부 CDF의 전체 분모+조건부 분자를 기존 population_scope enum으로 오라벨하거나 부분 분모로 재정규화하지 않는다. 새 scope adapter/DTO/재귀 허용목록이 미구현인 동안 제안 필드는 반환하지 않고 신규 결과는 pending/HOLD하며 기존 성공값을 보존한다.
- 조건부 대상 분류·이행: 비대상 검증 baseline 보존, 정확 대상만 조건 가드, 명부/버전/head 부재와 known-conditional 공급자 오류 시 무조건 fallback 거부, client method/분류/검증 flag 주입 거부, 최소 safe_code 후보 및 미등록 코드 거부를 같은 SHA에서 검증한다. 계약 등록과 실제 구현/DB/운영 완료는 구분한다.

## 실제 운영의 남은 자료

- 사용자 제공 자료 기반 자체 추정 공동분포·대학 환산곡선의 보정/holdout/민감도 검증과 estimated_weights 발행; 기획 추가 계약·자료팀 prototype 연계
- Supabase/Drive 실제 계정·고정 폴더·승인 명부·권한 설정과 실제 연동 검수
- 저장 exact tail의 whole-mass 분모 투영은 닫힌 SHA 결속 유틸리티와 합성6건까지 구현했다. 실제 NativeDataProvider/선택 객체/공개 누백 DTO에는 연결하지 않았고, 검수된 binder 발행본과 운영 결속은 NOT_RUN이다. 반올림된 eligible 비율의 재비례·모형/CDF 재구성·학교별 materialization은 하지 않는다.
