# 1페이지 공식 자료·추정 표기·발행 전 시사

이 문서는 공통 명세 service_spec.json에서 생성한다. 현재 버전은 1.9.12이며 기획·라우팅·계층 문서를 같은 변경으로 갱신한다.

추정 총 지원자·추정 탈락자 2열을 유지한다. 대학 발표 공식 지표와 분리된 화면 파생값이며 자체 누백/예상컷/개인 분석을 1페이지에 추가하지 않는다.

## 추정 2열의 표시와 산술

| 열 | 산식 |
| --- | --- |
| 추정 총 지원자 | 동일 모집행의 공식 경쟁률 분모 모집인원 × 공식 경쟁률을 정확 소수로 계산한 뒤 0.5 이상 올림하여 정수 표시 |
| 추정 탈락자 | 공식 지원자수 A가 검수됐으면 A − 모집인원 Q − 충원인원 C, 없으면 ROUND_HALF_UP(Q × 경쟁률 R) − Q − C; 동일 모집행/통계 분모·단계 확인 및 결과 비음수 필수 |

- 발표 지표 뒤 별도 추정 2열에만 표시한다. 머리글에 추정을 명시하고 회색 배경·범례로 구분한다.
- 공식 지원자수 A가 없을 때는 검수된 모집인원 Q·경쟁률 R·충원인원 C를 모두 요구하고 하나라도 없으면 두 파생값 모두 ─다. 공식 A가 있을 때는 발표 영역 A를 표시하고 추정 총 지원자 칸은 ─, 추정 탈락자만 A−Q−C로 계산한다. 이 분기에 경쟁률 R은 필요 없으며 Q/C 결측·범위 불일치면 탈락자 칸은 ─다. 실제 0은 결측으로 바꾸지 않는다.
- 같은 학년도·대학/캠퍼스·모집단위·전형·모집군과 동일 통계 범위의 자료만 묶는다. 과거 경쟁률에 2027 모집인원을 곱하지 않는다.
- 곱셈의 모집인원은 경쟁률을 산출한 공식 분모다. 최초/이월 전/최종인원 중 이름이 비슷한 값을 임의 선택하지 않는다. 분모와 모집 단계가 확인되지 않으면 ─다.
- 공식 지원자수 A가 동일 학년도/캠퍼스/모집행/전형/군/통계 단계·대상으로 검수되면 공식 영역의 발표 지표로 표시한다. 추정 총 지원자 칸은 ─로 비우고 추정 탈락자 칸만 같은 Q/C 정의·범위에서 A−Q−C로 표시한다. 공식 A와 추정 Q×R을 같은 칸에 섞거나 병기하지 않는다. A−Q−C도 산술 추정이며 실제 불합격자수를 뜻하지 않는다.
- 지원자수는 history_metric의 metric_name·metric_definition·unit·publication_status·출처로 구분한다. 영문 고정 필드 applicant_count가 있다고 가정하거나 문자열 포함 검사만으로 지표를 합치지 않는다. 데이터팀이 검수한 의미 대응을 사용한다.
- 모집·충원은 명 단위의 비음수 정수, 경쟁률은 공식 정의에 맞는 유한 비음수 값만 사용한다. 문자열 원문·백분율·충원율·최종 예비번호·최종 등록인원을 충원인원으로 치환하지 않는다.
- 공식 경쟁률이 반올림된 값이면 역산 지원자수에도 오차가 생긴다는 주의 문구를 표시한다. 공식 지원자수를 복원했다고 설명하지 않는다.
- 추정 탈락자는 모집인원과 발표 충원인원을 차감한 산술 지표다. 합격 후 등록 포기·반복 충원 등의 차이를 반영하지 못하므로 실제 불합격자수나 합격확률로 해석하지 않는다는 주의 문구를 표시한다.
- 차감 결과가 음수이거나 정의/통계 범위가 충돌하면 ─와 산출 불가 사유를 표시한다. 임의 0 보정·음수 인원 표시·다른 학년도 대체는 하지 않는다.
- 추정값과 범례는 화면에서만 파생한다. DTO·source metric·native 발행 자료·운영 DB·데이터팀 공식 수치 검산에 넣지 않는다. 공식 수치 대조와 화면 산술 대조는 별도 영수증이다.
- 2027 모집인원 상자는 최초 인원·전체 변경분·공식 최종인원·상태/기준일을 그대로 구분한다. 과거 입결 표의 산술 재료로 사용하지 않는다.
- 대학 발표의 평균·50%·70%·75%·최저 등 원래 통계 위치와 이름/정의/단위/점수 척도를 그대로 보존한다. 75%컷을 70%컷·최저 합격점·합격권으로 바꾸지 않으며 예상70%·판단용 합격권과도 분리한다. 일부 모집행/학년도 검수는 학교 4개년 전체 입결 완전성이나 모델 전체 승인 증거가 아니다.

## 발행 전 시사 준비

선택한 준비 경로: C_local_review_package. 기존 C 최소 catalog 로컬 시사와 A 학교별 정규 부분 발행 착수를 병행한다. 실제 자료 검수·승인·불변 저장·선택을 건너뛰지 않으며 시사는 발행 판단을 대신하지 않는다.

| 안 | 방식 | 적용 조건 |
| --- | --- | --- |
| A | 검수 통과분 부분 발행 | 검수 완료 최소 학교부터 착수한다. 단일 활성 catalog에 맞게 누적 불변 판을 만들고 native/독립 값 대조/권한/승인/저장/선택을 각각 인수한다. source-only 상태를 일괄 변경하지 않는다. |
| B | 관리자 검수 시사 상태 추가 | 상태·API·DTO·권한·캐시/보안/발행 계약을 바꾸므로 별도 CR 검토 대상으로 남긴다. 현재 경로에 운영 draft 우회를 넣지 않는다. |
| C | 로컬 시사 꾸러미 | A 학교별 발행 착수와 병행하는 기존 로컬 시사 경로다. 별도 로컬 승인·명부·수신 보호·API/브라우저 영수증이 있어야 실제 완료다. |

- 검수한 최소 catalog native 후보·신뢰 SHA256·원본→native 계보·공식 지표 의미 대응·정확 비교 모집행과 기대값을 먼저 고정한다.
- local 선택명부의 path는 수신 PC 경로이며 신뢰 명부·승인 문서·수신 PC 시험 세션을 기존 로컬 계약으로 결속한다. 작성·형식 통과만으로 승인됐다고 간주하지 않는다.
- 1페이지 시사에는 catalog만 최소 선택한다. 2~4페이지 산출용 exam_pack/total_model/conversion/percentile/analysis 등의 승인 근거는 각 기능이 필요할 때 별도로 준비한다.
- catalog-only 시사는 기존 local factory로 가능하다. /health/ready의 local_ready=true·production_ready=false 및 real_data.status=hold/exam_binding=NOT_PROVIDED를 Page1 자료 자체의 승인·API/기대값 인수와 구분한다. health 정상으로 전체 2~4페이지 준비 완료를 주장하지 않는다.
- 가상 학생 성적과 로컬 시험 subject만 사용하며 운영 DB·발행 상태를 바꾸지 않는다. 메모리 저장 결과는 재시작 시 유실되고 실제 학생 저장 완료로 표시하지 않는다.
- 부족한 자료와 미승인 모형은 기존 pending/503으로 보존한다. 4페이지까지 시사를 위해 숫자·곡선·판단을 만들어 넣지 않는다.
- 화면팀이 수신본 해시/선택명부/화면 SHA·역할·자료 버전과 공식 지표 대조·화면 산술 대조·브라우저 전달물 결과를 별도로 기록한다.
- v6 고정 native와 최신 원자료/정제 포인터는 다른 버전이다. 검수한 후보의 정확한 source/native 버전·해시와 현재 정본 대비 변경/제외 범위를 기록한다. 모집인원 object가 없는 카탈로그는 recruitment.read의 pending/recruitment_not_published와 빈 추정 칸이 정상이며 이를 0으로 채우지 않는다.

학교/모집행·지표 범위·결측·PK/공식 근거·native 변환·독립 대조·승인 담당이 고정된 뒤 담당자가 예상 시점을 기록한다. 저장 건수로 날짜를 약속하지 않는다.

외부 화면팀이 수시 JSON의 식별·범위·본체 반입·공개 후 비공개/반입분 삭제·현재 정시/본체에서 미사용이라고 FE-SOURCE-02로 회신했다.

상태: report_received_closed_for_jungsi_non_use_external_EduTouch_DB_and_authority_NOT_RUN.

- 파일 식별/출처·수시 범위/본체 반입 관계/현재 미사용 보고는 수신했다. 다른 PC 원본·본체 PR/DB 잔존 수·외부 사용자 삭제 승인 사실을 이 작업에서 독립 검증한 것으로 적지 않는다.
- 정시 정본/source 등록·jungsi_backend·정시 페이지와 독립 흐름으로 유지한다. 수시 자료를 정시 native/1페이지 발행 후보로 자동 조인하거나 재반입하지 않는다.
- 화면팀의 본체 삭제 완료 보고는 외부 소관 이력으로 기록한다. 여기서 본체 DB 삭제·복원·재반입·설정 제거를 실행하거나 승인하지 않는다. 기존 원본/스크립트/마이그레이션/이력은 보존한다.
- 현재 정시에서 사용하지 않는 흐름의 회신은 수신/분리 확인으로 마감한다. 향후 다시 사용하려면 원본 hash·출처/공개 이용 범위·전형 분류·권한·현재 DB/화면 경로를 별도 검수한다.
