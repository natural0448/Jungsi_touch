# 정시터치 재시작 후 다른 PC 개발 인수인계

시스템기획팀이 2026년 10월 14일 재시작 후 작업을 인계한다. 현재 통합 코드 기준은 `develop`의 `00b490a6a97948c0fb59a1e887f1e25ff55ad512`, 공통 명세는 **1.9.53**이다. 개발팀의 Supabase Edge 22개 API 이식 후보는 별도의 미커밋 보관본으로 전달한다. 실제 사용자 인증과 운영 배포를 완료한 상태는 아니다.

이 문서는 위 커밋에 대한 인계 기록이다. 이후 개발 기준은 최신 `docs/current/service_spec.json`과 같은 커밋의 생성 문서를 따른다. 비공개 자료 경로·현재 포인터 해시·미커밋 소스 복원 목록은 사용자가 요청한 Google Drive 인수인계 꾸러미에서 받는다.

개발팀의 작업 체크아웃은 기획 1.9.53을 병합했고, 이식 후보가 미커밋 상태로 남아 있다. 원격 애플리케이션 브랜치만 clone하면 이 후보를 받을 수 없다. Drive에서 받은 소스 목록과 SHA256을 확인해 별도로 인수해야 한다. 이전 체크아웃의 진행 중 merge와 로컬 변경은 보존한다.

## 다른 PC에서 재개하는 순서

1. Drive 인수인계서와 팀별 체크포인트를 먼저 읽고 코드·꾸러미의 해시를 대조한다. 변경된 현재 포인터를 이전 인계본으로 되돌리지 않는다.
2. 기존 데이터 작업 폴더를 덮어쓰지 않는 새 코드 위치에서 저장소를 받는다. 현재 원격이 인계 기준보다 진전했다면 Git 변경 목록부터 확인한다.
3. 시스템기획팀은 `develop`, 애플리케이션 개발자는 `feature/application-pre-data-platform`, 화면 개발자는 `feature/presentation-foundation`을 재사용한다. 새 브랜치는 필요성과 부모를 등록한 경우에만 만든다.
4. 개발팀의 미커밋 소스는 인계 기준 커밋과 원 파일 해시를 먼저 확인하고 복원한다. 충돌 파일은 원형을 보존한 뒤 담당자가 해결한다. reset, clean, merge abort, 잠금·캐시·기존 파일 삭제로 해결하지 않는다.
5. 새 PC의 Python·Deno 실행기와 보존형 의존성 준비 절차는 저장소의 런타임 잠금 파일을 따른다. 각 clone의 `core.hooksPath=.githooks`를 설정한다. 비밀 설정과 인증 세션은 소스 꾸러미에 포함되지 않는다.
6. 기존 PC의 DB writer가 인계 상태임을 확인한 뒤 데이터팀 한 명만 변경을 재개한다. 기존 명령 ID의 실행 결과와 현재값을 대조해 중복 등록을 막는다.

```powershell
# 대상 폴더가 존재하면 새 경로를 정해 기존 폴더를 보존한다.
git clone --branch develop https://github.com/natural0448/Jungsi_touch.git 'C:\dev\Jungsi_touch-code'
Set-Location -LiteralPath 'C:\dev\Jungsi_touch-code'
git status --short --branch
git rev-parse HEAD
git config --local core.hooksPath .githooks
```

## 남은 실제 운영 업무

| 담당 | 다음 업무 | 완료 조건 |
| --- | --- | --- |
| 개발팀 | 미커밋 22개 API 이식 후보의 런타임 조립과 소스 등록 | 최종 커밋의 함수 경로·소스 해시·명세 operation 등록이 일치하고 정상 검사와 CI가 통과 |
| 개발팀과 데이터팀 | 승인된 시험팩·카탈로그·환산식·전체 및 대학 누적곡선·판단 자료 선택 | 불변 원본의 bytes·SHA·버전·적용 범위·발행 승인과 실제 엔진 입력이 일치 |
| 개발팀 | 실제 DB 트랜잭션과 재실행·경합 검수 | 같은 명령 재실행, 충돌, 소유권, native 자료형과 출처의 실제 영수증 확보 |
| 개발팀과 화면 개발자 | 실제 사용자 JWT와 관리 OTP 검수 | 같은 Bearer의 사용자·프로젝트·AAL2·본인 active 상태·현재 학교 권한을 서버에서 확인하고 허용·거절 사례 검수 |
| 개발팀 | 기존 Supabase Edge에 운영 후보 배포 | 실제 함수 버전·커밋·경로·quota 설정과 실행 영수증 결속 |
| 화면 개발자 | `/jeongsi` 합성 모드를 live BFF로 연결 | 사용자 Bearer 및 서버 전용 relay 송신, 운영 응답·캐시·비노출·소유권을 실제 브라우저에서 검수 |
| 시스템기획팀 | 기획·라우팅·3티어·코드 색인과 인수 상태 갱신 | 같은 Git 스냅샷으로 문서 검사, 소스 등록, native와 배포 증거를 각각 반영 |

계정 주인의 관리자 화면 진입은 확인했지만, 서비스 API의 실제 JWT·AAL2 검수는 별도다. 관측한 `/jeongsi`는 합성 응답 화면이다. 재시작 이후 인증 상태는 새 PC에서 계정 주인이 직접 로그인·OTP를 수행해 다시 확인한다.

공통 명세의 22개 API 소스 등록은 이 코드 기준에서 `NOT_PORTED`다. 미커밋 후보의 합성 테스트 결과를 최종 커밋의 실제 DB·사용자 JWT·배포 인수로 승격하지 않는다. 운영 준비는 `production_ready=false`다.

## 데이터와 비용의 운영 범위

현재 데이터 조회는 데이터팀의 단일 정본과 `jungsi_data_ingest.admission_results_current`를 사용한다. 원본·변경 이력은 보존하며, 정정 명령은 예상 이전 해시와 현재 지문을 결속하고 포인터를 마지막에 갱신한다. 학교별 2024~2027 검수 근거를 재사용하고, 불일치하거나 새로 필요한 원문 범위만 다시 확인한다.

운영 서비스는 **Google Drive와 기존 Supabase**로 제한한다. 신규 호스팅·요금제 변경·추가 프로젝트·유료 부가 기능은 이번 인계의 범위가 아니다. 기존 유료 Edge의 최대 실행 시간 400초와 유휴 시간 150초는 시간 제한과 작업 lease 설계에 반영돼 있다. 애플리케이션 제한을 정했다는 이유만으로 외부 과금 통제가 완료된 것으로 기록하지 않는다.

## 위치 그래프 후속 작업

합성 화면의 전체는 국어+수학+탐구1+탐구2이고, 조합별 두 과목 평균은 국어+수학+(탐구1+탐구2)/2다. 합성 누적곡선도 서로 달라 같은 위치값을 보장하지 않는다. 아래 값이 더 정확하다는 근거로 사용하지 않는다. 전체 엔진의 합산 정의는 유지하고, 화면 개발자가 합산·평균의 명칭과 합성 표시를 명확히 해야 한다. 조합별 DTO는 정식 채택 전 후보이며 승인 곡선이 없으면 보류한다.

## 모든 에이전트의 문서 동기화

작업 시작 시 AGENTS.md, [공통 명세](../current/service_spec.json), [개발현황과 문서 동기화](../current/개발현황_문서동기화.md), [코드 라우팅 색인](../current/code_routing_index.json), [보안 개발기준](../current/외부접근_데이터보호_개발기준.md)을 먼저 읽는다. 이후 Git 변경 파일과 저장된 검사 결과를 기준으로 범위를 좁힌다.

기능 변경에는 요구사항 ID·화면/API 경로·권한·담당 계층·검증을 함께 반영한다. 생성 문서를 단독 편집하지 않고 공통 명세와 생성 도구에서 갱신한다. `scripts/audit_documentation_sync.py`의 변경 파일 검사와 정상 훅·CI를 통과한 같은 커밋을 인수한다. 수동 풀 스캔을 반복해 문서 불일치를 해결하지 않는다.

원자료·실제 성적·모형·내부 정본·환경변수 파일은 Git에서 제외한다. 파일·폴더·이전 버전·작업 결과는 사용자가 삭제 대상과 범위를 명시하기 전까지 보존한다.
