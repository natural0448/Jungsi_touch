# 서비스 기획 v0.1

작성일: 2026-09-23 · 상태: 사용자·첫 자료 화면·실제 수능 환산 확정 / 예시 파일 기반 상세 설계 대기

## 확정된 제품 방향

사용자 답변(2026-09-23)에 따라 **교사·입시상담자가 먼저 개인 성적 없이 대학의 정시 성적자료 정리본을 확인하고, 실제 수능 성적을 적용해 환산점수·지원 후보를 비교하는 상담 도구**로 정한다. 입력 성적은 실제 수능만 지원한다. 첫 적용 학년도·대학·개인 성적 저장 여부는 추가 결정 대상이다.

사용자가 제공할 예시 파일을 첫 화면과 항목 구성의 기준으로 삼는다. 현재는 파일을 받기 전이므로 ‘정시 성적자료’의 세부 지표·단위·학년도·대상 집단과 표 배치를 확정하지 않는다.

## 해결할 사용자 문제

대학·학년도·전형마다 흩어진 정시 자료를 같은 맥락에서 확인하기 어렵다. 모집단위가 변경되면 과거 자료와의 관계가 끊기고, 모집인원의 기준 시점과 점수 지표가 다르면 비교 결과를 오해할 수 있다. 이 문제를 해결하는 것을 첫 서비스 가설로 둔다.

서비스의 약속은 ‘대학의 정시 성적자료를 먼저 이해하고, 실제 수능 성적을 적용하면 상담자가 후보별 환산 결과와 근거를 설명할 수 있게 한다’이다. 합격 가능성이나 지원 적합성 판단의 범위는 기능 선택과 데이터 검증 후 결정한다.

## 사용자와 필요한 결과

| 사용자 | 대표 작업 | 필요 화면·권한 | 기획에서 달라지는 점 |
|---|---|---|---|
| 교사·입시상담자 — 첫 사용자 | 대학 성적자료를 열람하고 학생의 실제 수능 성적으로 후보 비교 | 넓은 비교표, 근거 보기, 상담용 결과 저장 후보 | 다중 학생 관리와 기관 권한 필요 여부 |
| 학생·학부모 — 후속 대상 후보 | 본인 조건에 맞는 대학·전형 탐색 | 쉬운 설명, 조건 필터, 관심 후보 | 모바일 사용, 용어 설명, 성적 입력 부담 |
| 내부 데이터 운영자 | 학교별 자료 대조 및 정정 | 4개년 검수판, 변경 내역, 공개 관리 | 편집 충돌·검토 책임·배포 절차 |

첫 고객은 교사·입시상담자로 확정한다. 내부 데이터 운영자는 서비스 유지에 필요한 역할이며, 학생·학부모의 직접 이용은 후속 범위다. PC에서 넓은 비교표를 사용하는 상담 흐름을 먼저 검토하되 지원 기기는 별도 합의한다.

|---|---|---|---|

| 별도 확장 후보 | 합격 예측·자동 지원 조합 | 결과 정의·학습 데이터·평가 설계 | 별도 기획과 품질 검증 |

첫 화면은 수능 성적 입력을 요구하지 않는다. 자료 열람과 성적 적용을 두 흐름으로 제공하며, 지원할 학교 범위는 예시 파일과 적용 학년도를 확인한 뒤 정한다. 로그인 필요 여부는 개인 성적 입력 여부와 다른 정책이므로 미정으로 남긴다.

## 첫 사용 흐름

### A. 개인 성적 없이 자료 열람

1. 첫 화면에서 대학의 정시 성적자료 정리본을 연다.
2. 예시 파일의 항목에 맞춰 학년도·대학·모집단위·전형 등의 조건을 고른다.
3. 자료의 지표·점수 기준·대상 집단·출처·기준일을 확인한다.
4. 필요한 상세 내용과 4개년 모집행의 변화 관계를 확인한다.
5. 학생 성적을 적용할 때 ‘내 학생 성적으로 비교’ 흐름으로 이동한다.

조건·지표·탭과 표의 실제 배치는 예시 파일을 보고 확정한다. 자료가 없거나 아직 공개되지 않은 경우에는 상태를 표시하며 성적 입력을 강제로 요구하지 않는다.

### B. 실제 수능 성적을 적용한 상담

1. 상담자가 적용 학년도와 수능 시행 연도를 선택하고 상담용 성적 사례를 연다.
2. 국어·수학·탐구의 과목과 표준점수·백분위·등급, 영어·한국사 등 해당 규칙에 필요한 값을 입력한다.
3. 앞서 본 자료 또는 지역·대학·전형·군·희망 분야 조건에서 계산 후보를 고른다.
4. 지원하는 모집행을 일괄 계산하고 미지원·입력 부족·공식 규칙 미공개 사유를 함께 본다.
5. 대학별 환산점수·만점·반영 방법·지원 조건·모집정보를 비교한다.
6. 계산 근거에서 영역별 반영값·가산점·반올림·공식 출처를 확인한다.
7. 후보를 좁히고, 채택한 기능 범위에 따라 상담 결과를 저장하거나 출력한다.

성적을 바꾸면 이전 계산 결과에 ‘입력 변경으로 재계산 필요’를 표시한다. 이전 결과와 새 입력이 섞인 상태를 상담 자료로 사용하지 않게 한다. 대학별 점수 만점이 다르므로 환산점수 크기만으로 대학을 일렬 순위화하지 않는다.

U00을 첫 진입 화면으로 두고 U05·U04·계산 근거 보기로 이어지게 한다. U00의 지표·필터·배치는 예시 파일에서 도출한다. A01·A02의 운영 담당은 조직이 정해지면 배정한다. 첫 버전에 별도 대규모 관리 시스템을 만들 필요는 없으며, 핵심 검수·승인 흐름부터 구현한다.

### 4개년 비교 화면의 표현 원칙

- 연도 열과 모집행 카드를 사용한다. 한 연도에 대응 모집행이 여러 개이면 모두 표시한다.
- 당시 학과명·학교명을 보존하고 현재 명칭은 별도 안내한다.
- 동일·명칭변경·통합·분리와 ‘이 모집단위로 입학 후 선택 가능한 전공’을 다른 관계로 표시한다.
- 연결이 없으면 ‘후속 관계 확인 중’과 사유를 표시한다. 관계 없음만으로 ‘폐과’를 표시하지 않는다.
- 모집인원의 기준·수시이월 반영·추가 정정을 선택하거나 구분해서 본다.
- 인원이 다른 모집군·전형의 행은 각 행으로 유지한다. 학부와 내부 전공 인원을 중복 합산하지 않는다.

| 검수 담당 | 근거를 포함한 정정 제안, 본인 작업 상태 기록 |
| 공개 담당 | 필수 검증 확인, 배포본 공개·복귀 결정 |
| 기관 관리자 | 기관 기능을 채택한 경우 구성원과 접근 범위 관리 |

기관·개인 성적 보관을 채택하면 소유자와 기관 경계를 서버에서 검사한다. 실제 학생 정보는 보관 목적·기간·열람 권한·철회 처리 방식을 정한 뒤 도입한다. 운영 개인정보의 보관 종료 정책은 별도 합의 대상이며, 프로젝트 파일 삭제 금지 규칙을 영구 개인정보 보관 정책으로 해석하지 않는다.

## 입시결과와 예측의 경계

정시 성적자료의 실제 구성은 예시 파일을 확인해 정한다. 그 자료가 입시결과를 포함한다면 결과 대상 학년도, 모집행, 지표 이름, 대상 집단, 점수 체계, 만점, 공표 기준과 출처를 함께 저장한다. 평균·70% 지점·최저·최종 등록자·최초 합격자 등 정의가 다르면 같은 열에서 같은 의미로 취급하지 않는다. 이 지표명은 데이터 정의에서 구별할 예시이며 첫 화면의 확정 컬럼이 아니다. 실제 표시 항목은 예시 파일과 출처에 따라 결정한다.

과거의 특정 점수와 올해 환산점수의 차이만으로 합격 확률을 계산하지 않는다. 예측을 채택한다면 ‘무엇을 예측하는가’, 과거 전형·모집단위 변경 처리, 연도 순서에 따른 별도 평가, 결과 공개 시점에 따른 정보 누출 방지, 미지원 표본의 처리 방식을 먼저 결정한다.

## 상담 비교표의 최소 항목

| 묶음 | 표시할 항목 |
|---|---|
| 입력 사례 | 상담용 이름 또는 별칭, 실제 수능 시행 연도, 적용 학년도, 성적 입력 버전 |
| 지원 후보 | 대학·캠퍼스·모집단위·전형·군·지원 조건 |
| 계산 결과 | 환산점수, 만점, 산출 상태, 사용한 점수 지표, 반영 방법 |
| 계산 설명 | 영역별 반영·가산·감산·반올림, 규칙 버전, 공식 근거 |
| 모집정보 | 모집인원·자료 단계·선발 조건·기준일 |
| 상담 판단 보조 | 희망 조건 일치 여부, 확인해야 할 자격, 미공개 항목, 후보 메모 |

서로 다른 대학의 환산점수를 공통 척도로 표시하는 기능은 근거를 먼저 설계한다. 만점 대비 비율만으로 합격 가능성이나 대학 간 유불리를 확정하지 않는다. 과거 입시결과와의 차이 표시도 점수 체계·규칙·대상 집단의 호환성을 확인한 경우에만 제공한다.

## 출시 범위와 성공 판단

첫 시범 서비스는 검수된 학교 묶음부터 제공하고, 추가 학교는 같은 공개 기준으로 늘리는 방안을 제안한다. 전국 원문을 확보했다는 이유만으로 모든 모집행의 검증 완료를 표시하지 않는다.

성공 여부는 ‘개인 성적 없이 대학의 정시 성적자료를 찾고 이해할 수 있는가’, ‘선택한 모집행의 근거를 찾을 수 있는가’, ‘4개년 변화와 미확정 상태를 올바르게 설명하는가’, ‘지원하는 계산을 재현하는가’로 먼저 평가한다. 사용 시간·성공률·검색 속도 등의 수치 목표는 주 사용자와 시험 환경을 정한 후 승인한다.
