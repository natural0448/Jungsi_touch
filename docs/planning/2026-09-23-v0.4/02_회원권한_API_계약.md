# 회원 권한과 API 계약 v0.4

작성일: 2026-09-23 · [회원·첫 페이지 기획](00_회원등급_첫페이지_기획.md)

## 1. 권한 모델

일반가입자와 유료가입자를 서비스 이용권한으로 구분한다. 유료 분석 권한은 서버가 관리한다. 브라우저의 버튼 상태, localStorage, 요청의 is_paid 값, .env의 회원 등급값으로 판정하지 않는다.

.env는 결제 연동을 채택한 경우 그 서버 설정·비밀값을 공급하는 수단으로 사용할 수 있다. 개별 회원의 결제·이용권한은 회원별 서버 데이터다. 팀원의 전체 코드·데이터 접근 방침과 이용자의 유료 권한은 별개다.

| 주체·상태 | 과거 4개년 조회 | 새 개인 분석 |
|---|---|---|
| 로그인한 일반가입자 | 허용 | 거절, 유료 분석 안내 |
| 유료 분석 권한이 현재 유효한 가입자 | 허용 | 허용 |
| 분석 권한 만료·회수 | 일반 조회 허용 | 새 분석 거절 |
| 비회원 | 실제 자료 공개 범위 미정 | 거절 |
| 내부 공동 제작자 | 내부 계정으로 전체 자료 접근 | 운영 계정·테스트 계정의 용도 구분 |

가격·이용기간·정기결제·무료 체험은 아직 미정이다. 월간 구독이나 자동 갱신을 확정 요구로 저장하지 않는다.

## 2. API 분리 제안

| API | 허용 대상 | 입력 | 결과 |
|---|---|---|---|
| GET /api/v1/me/entitlements | 로그인한 가입자 | 없음 | 현재 이용권한과 만료 정보(해당 시) |
| GET /api/v1/admission-history | 일반·유료가입자 | 대학명·학과명·허용된 조회창·페이지 커서 | 승인된 4개년 결과, 자체 누적, 군·인원 |
| POST /api/v1/score-comparisons | 유효한 유료 분석 권한 | 실제 수능 성적 1개·선택 후보 | 본인 성적 분석 |
| 개인 결과 저장·재조회 | 별도 정책 후 | 결과 ID 등 | 소유자·상담 관계 및 상품 권한 추가 확인 |
| 내부 원본·모델 관리 | 내부 계정 | 승인된 관리 작업 | 서비스 공개 API와 분리 |

일반 조회는 점수나 계산식을 받지 않는다. 임의 점수·대량 스캔 파라미터·권한 상승 필드는 서버에서 거절한다. 유료 API가 계산을 끝낸 후 화면만 가리는 방식으로 구현하지 않는다.

권한 조회 응답은 화면 메뉴 구성에 쓸 수 있지만 분석 API는 호출할 때마다 서버의 현재 권한을 다시 확인한다. 세션에 남은 오래된 유료 표기만으로 만료 후 분석을 계속 허용하지 않는다.

## 3. 개인 분석 요청 순서

1. 세션과 회원을 확인한다.
2. 현재 유료 분석 권한·적용 범위·만료를 확인한다.
3. 요청량·후보 수·작업 비용 한도를 확인한다.
4. 입력과 해당 시험·대학 반영 조건을 검증한다.
5. 서버 전용 엔진으로 계산한다.
6. 본인에게 허용된 결과만 반환한다.

성적 저장과 과거 결과 재열람은 아직 별도 정책이다. 가입 등급을 바꿨다고 다른 이용자의 성적 접근이나 교사의 다중 학생 관리 권한이 자동 부여되지 않는다.

## 4. 결제 연동 준비 범위

결제 방식을 선정하면 결제 완료·취소·환불 등 서버에서 검증한 사건을 이용권한과 연결한다. 브라우저의 ‘결제 성공’ 이동 주소나 임의 파라미터로 유료 권한을 활성화하지 않는다. 중복 통지·재시도에도 동일한 권한 변경이 한 번만 적용되도록 설계한다.

권한 만료·회수 시 신규 분석은 차단하되 기존 자료·이력은 보존한다. 삭제가 필요하면 프로젝트의 명시적 삭제 허용 규칙을 따른다. 취소 시 즉시 종료인지 남은 기간 유지인지, 과거 결과를 어디까지 볼지는 상품 정책으로 결정한다.

## 5. 첫 페이지 데이터 계약

handoff의 [membership-contract.json](handoff/membership-contract.json)은 디자인·개발 협의용 초안이다. 운영 API나 표준 OpenAPI 스키마는 아니다.

- 조회창은 4개의 결과 학년도로 정의하며 실제 학년도는 미정이다.
- 대학·학과 묶음 아래 연도별 모집행을 보존한다.
- 각 연도에는 합격권·상위 70% 결과 객체를 모두 두고 점수·자체 누적·자료 상태를 별도로 표현한다.
- 출처의 결과 기준과 자체 누적 분포 버전을 함께 기록한다.
- 표시 비율은 내부 0~1을 %로 변환한다.
- 합성 예시는 실제 입시결과로 게시하지 않는다.
- 일반 조회의 응답은 개인 성적·개인 분석 결과를 포함하지 않는다.

## 6. 구현 후 확인할 시나리오

- 일반가입자가 대학·학과로 검색해 4개년 결과를 조회할 수 있다.
- 유료가입자는 같은 첫 페이지와 개인 분석을 모두 이용할 수 있다.
- 일반가입자가 주소를 직접 호출하거나 브라우저의 회원 표시를 바꿔도 개인 분석은 거절된다.
- 유료 권한이 만료된 뒤의 새 분석은 거절되고 과거 입시결과 조회는 유지된다.
- 조회 응답에 숨겨진 개인 분석값·전체 누적표가 포함되지 않는다.
- 이월·미공개·실제 0 인원이 구분되고 각 연도의 군·인원을 사용한다.
- 합격권과 70% 지점 등 서로 다른 결과 기준을 같은 열의 동일 의미로 합치지 않는다.
- 4개년 일부 결측·학과 개편·전형 분리를 사실대로 표시한다.

현재는 위 조건을 기획한 단계이며 실제 권한 차단이나 결제 연동 테스트를 통과했다는 의미는 아니다.
