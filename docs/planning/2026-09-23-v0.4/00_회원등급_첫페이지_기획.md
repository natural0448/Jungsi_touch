# Jungsi_touch v0.4 — 회원 등급과 첫 페이지

작성일: 2026-09-23  
상태: 사용자 요구 반영 및 화면·API 기획. 운영 서비스 구현 전.

## 이번에 확정한 요구

| 항목 | 결정 |
|---|---|
| 가입자 구분 | 일반가입자 / 유료가입자 |
| 일반가입자 제공 범위 | 4년치 입시결과 자료 조회 |
| 유료가입자 제공 범위 | 일반가입자의 조회 기능 + 자신의 실제 수능 성적 입력·분석 |
| 첫 페이지 | 대학명·학과명 검색 → 학교·모집단위별 4개년 정시 입시결과 |
| 기본 수치 | 정시 환산점수, 우리가 산출한 누적백분위, 모집군, 선발 인원 |
| 입시결과 기준 | ‘합격권’과 ‘상위 70%’를 구분해 모두 제공. 각 기준별 환산점수·자체 누적백분위 표시 |
| 표현 참고 | 고속성장 분석기의 과거 입시결과 및 모집군·정원 영역 |
| 기존 조건 유지 | 학생·학부모 중심, 교사·입시담당자 부 사용자, 실제 수능만 입력, 3티어, 핵심 계산 서버 수행 |
| 팀 내부 | 공동 제작자 전원 전체 코드·데이터 접근 |

무료/유료 상품 가격, 이용기간, 정기결제 여부, 분석 횟수는 확정하지 않았다. 비회원에게 실자료를 어디까지 보여 줄지도 별도 결정 대상이다. 본 회원용 첫 페이지는 로그인한 일반/유료가입자를 기준으로 한다.

[v0.2 서비스·누적 설계](../2026-09-23-v0.2/00_기획_안내.md), [v0.3 보안·협업 설계](../2026-09-23-v0.3/00_3티어_보안_설계.md)를 이어 적용한다. v0.3에서 미정이었던 개인 분석의 이용권한은 유료가입자로 정한다.

## 1. 기능 권한

| 기능 | 일반가입자 | 유료가입자 |
|---|---|---|
| 대학명·학과명 검색 | 허용 | 허용 |
| 4개년 입시결과 조회 | 허용 | 허용 |
| 해당 결과의 환산점수·자체 누적백분위 | 허용 | 허용 |
| 각 학년도 모집군·선발 인원 | 허용 | 허용 |
| 자신의 실제 수능 성적 입력·서버 분석 | 제공하지 않음 | 허용 |
| 개인 성적의 대학별 환산·추정 위치·후보 비교 | 제공하지 않음 | 허용 |
| 원본·전체 누적표·핵심 엔진 다운로드 | 일반 서비스에 제공하지 않음 | 일반 서비스에 제공하지 않음 |
| 다중 학생 관리·기관 관리·성적 공유 | 별도 미정 | 별도 미정 |

교사라는 사용자 성격만으로 유료 기능이나 다른 학생의 성적 접근이 자동 부여되지는 않는다. 가입 등급과 객체 접근권한은 별개다. 일반가입자에게 개인 성적을 먼저 수집한 뒤 결과만 잠그는 흐름은 이번 범위에 넣지 않는다.

## 2. 첫 페이지의 정보 구조

첫 페이지의 목적은 학교·학과를 찾아 과거 4개년 결과를 바로 확인하는 것이다. 첫 화면의 중심을 개인 점수 입력이나 합격 가능성 판단으로 바꾸지 않는다.

1. 상단: 서비스명, ‘4개년 입시결과’, ‘내 성적 분석’, 회원 상태.
2. 검색: 대학명, 학과명. 둘 중 하나만 입력해도 검색하고 두 값을 넣으면 함께 충족하는 모집행을 찾는 안을 제안.
3. 결과 묶음: 대학명·모집단위명과 필요한 전형 구분.
4. 연도별 행: 학년도, 모집군, 선발 인원, 합격권 환산점수·자체 누적백분위, 상위 70% 환산점수·자체 누적백분위.
5. 보조 설명: 결과 지표 정의, 당시 점수 기준, 누적 비교집단, 출처·기준일을 펼쳐 확인.
6. 개인 분석 진입: 일반가입자는 유료 분석 안내, 유료가입자는 실제 수능 입력으로 이동.

기본 표시 항목은 사용자 요청 범위로 제한한다. 경쟁률·충원·예상/적정/소신 지원선·합격 가능성·개인 점수 등은 이 페이지의 기본 열에 추가하지 않는다.

‘전형’은 별도 숫자 지표가 아니라 같은 학과의 복수 모집행을 구분하기 위한 정보다. 같은 학과명이라도 일반전형·지역인재·모집군이 다르면 같은 한 행으로 합치지 않는다.

## 3. 권장 배치

대학·학과별 묶음 아래 4개년을 행으로 배치한다.

| 학년도 | 모집군 | 선발 인원 | 합격권 환산점수 | 합격권 자체 누적 | 상위 70% 환산점수 | 상위 70% 자체 누적 |
|---|---|---|---|---|---|---|
| 선택 범위의 최근 연도 | 해당 연도 값 | 해당 연도 값 | 당시 기준 점수 | 추정 상위 % | 당시 기준 점수 | 추정 상위 % |
| 이전 연도 | 해당 연도 값 | 해당 연도 값 | 당시 기준 점수 | 추정 상위 % | 당시 기준 점수 | 추정 상위 % |
| 이전 연도 | 해당 연도 값 | 해당 연도 값 | 당시 기준 점수 | 추정 상위 % | 당시 기준 점수 | 추정 상위 % |
| 이전 연도 | 해당 연도 값 | 해당 연도 값 | 당시 기준 점수 | 추정 상위 % | 당시 기준 점수 | 추정 상위 % |

상단 헤더는 ‘합격권’과 ‘상위 70%’ 두 묶음으로 나누고 각 아래에 환산점수·자체 누적백분위를 둔다. 한쪽 결과만 확보됐으면 나머지는 상태를 표시하며, 한 기준의 값을 다른 기준의 대체값으로 채우지 않는다. 출처의 실제 지표 정의를 검증해 상세 설명에 연결한다.

모바일에서는 각 학년도를 한 묶음으로 재배치한다. 중요한 수치를 탭 뒤에 숨기거나 첫 화면에 필요 없는 요약 지표를 늘리지 않는다.

화면 예시에 쓰는 2023~2026과 가상 수치는 출시 연도·실제 데이터 확정이 아니다. 실제 4개년 조회 범위는 결과 공표와 검수 범위를 기준으로 정한다. 원문 수집의 2024~2027 범위를 입시결과가 모두 존재하는 범위로 간주하지 않는다.

## 4. 두 종류의 누적백분위

- **일반가입자용:** 특정 대학·모집단위·학년도·결과 기준의 환산점수에 대응하는 자체 누적백분위. 서버에서 검증 후 미리 생성한 조회 자료다.
- **유료가입자용:** 해당 이용자의 실제 수능 성적을 대학별로 환산한 뒤 얻은 추정 위치. 권한이 있는 요청에 대해 서버가 계산한다.

일반가입자가 조회할 수 있는 전자는 유료 기능의 우회 제공이 아니다. 개인 입력과 무관한 과거 자료 제공이라는 확정 상품 범위에 해당한다.

두 경우 모두 전체 누적표·가상 응시집단·모델 파라미터는 브라우저에 전달하지 않는다. 일반 조회 요청에는 점수·구간 스캔·임의 환산 요청을 받지 않는다.

## 5. 아직 정할 항목

- 표시할 정확한 4개 학년도.
- 두 기준의 구체적 정의와 확보 방식: 제공 범위는 ‘합격권 + 상위 70%’로 확정했다. 출처의 상위 70%가 최종등록자 70% 지점인지, 평균 등 다른 지표인지 확인하고 합격권의 추정·공식 여부도 구분한다.
- ‘선발 인원’의 기준: 최종 모집인원인지 실제 선발/등록인원인지. 원본의 ‘정원’을 모든 연도의 실제 등록인원으로 해석하지 않는다.
- 유료 가격·기간·결제 방식·이용량과 만료 후 과거 개인 결과 조회.
- 비회원 공개 범위, 성적 저장·공유 정책, 첫 대학 범위와 기술 스택.

이 항목이 미정이어도 회원 기능 분리와 화면 구조는 확정 요구대로 준비할 수 있다. 점수 기준은 화면·DB에서 명시적으로 표시해 서로 다른 지표가 섞이지 않게 한다.
