# 1페이지는 대학 발표 결과, 3페이지는 학생 성적 분석

2026-09-30 사용자 요구. 두 페이지의 공통점은 대학명·학과명을 입력하는 검색 구성이다. 데이터의 성격과 권한은 아래처럼 구분한다. 이전 v0.11의 유료 권한 정정은 유지한다.

| 구분 | 1페이지 | 3페이지 |
| --- | --- | --- |
| 목적 | 대학이 발표한 입시결과 조회 | 내가 검색한 대학·학과에서 내 성적의 의미 확인 |
| 이용자 | 일반·유료가입자 | 유료가입자만 |
| 성적 입력 | 필요 없음 | 학생 환산·지원가능성·유불리 분석에 필요 |
| 주요 결과 | 발표 지표명·원래 결과치·단위·학년도·출처 | 내 환산점수·지원가능성·환산 유불리 |
| 자체 추정값 | 제공하지 않음 | 승인된 모델·비교 근거에 따라 별도 표시 |

## 1페이지: 발표 자료 그대로

대학이 공개한 지표의 명칭과 정의를 보존한다. 최종등록자 70% 기준 대학 환산점수, 백분위 평균 등은 서로 다른 지표이며 같은 종류의 점수로 바꾸어 표시하지 않는다. 대학이 특정 값을 공개하지 않았으면 미공개 또는 미확인 상태를 표시한다. 발표값이 없는 칸을 자체 누적곡선이나 올해 예측으로 채우지 않는다.

이전 화면의 ‘자체 누적’ 열과 업체 추정 합격권을 1페이지에 표시하던 방향은 이번 사용자 지시로 변경한다. 대학이 실제 발표한 백분위는 원 지표로 표시할 수 있지만, 우리 서비스의 추정 상위 누적과 구별한다. ‘합격권’이나 ‘상위70%’도 해당 대학이 그 정의로 발표했을 때만 대학 발표 결과로 취급한다.

현재 학년도 모집군·최초 선발인원·변경분·최종 모집인원 보조 정보는 대학의 공식 발표가 있을 때 해당 값과 기준일을 표시한다. 미공개는 0으로 변환하지 않는다. 4개년 조회는 유지하며, 예시의 2023–2026을 실제 적용 범위로 확정하지 않는다.

## 3페이지: 세 항목을 따로 판단

대학명·학과명 검색 결과 표와 상세에 다음 세 항목을 나란히 배치했다.

1. **내 환산점수:** 실제 성적 조합에 해당 학년도·모집단위·전형·모집군의 공식 반영식, 변환표, 가산점과 반올림을 적용한 점수다. 같은 대학 안에서도 반영식이 다르면 별도로 계산한다.
2. **지원가능성:** 해당 학과의 비교 가능한 입결과 올해 채택 예상 기준, 지원 조건을 반영한 검토 결과다. 도전·핵심 검토·여유·추천 범위 밖·확인 필요·조건 미충족을 구분한다. 현재 가상 분류는 통계적으로 보정된 합격확률이 아니다.
3. **환산 유불리:** 학생의 과목별 성적 조합이 그 대학 반영 방식에서 상대적으로 유리해지는지 확인한다. 지원가능성과 별개의 결과다.

가상 예시에서 예시가온대 경영학과는 915.20점·도전·환산 유리(+0.53%p), 같은 대학 경제학과는 915.20점·핵심 검토·환산 유리(+0.53%p)다. 예시해솔대 임상병리학과는 932.00점·여유 후보·환산 불리(-0.13%p)다. 유리하다는 이유만으로 합격 가능하다고 판정하지 않고, 불리하다는 이유만으로 지원 불가로 판정하지 않는다. 이 학교·수치·분류는 전부 가상이다.

대학별 환산점수의 만점이 다르므로 점수 크기나 만점 대비 비율로 유불리를 결정하지 않는다. 기존 유불리 설계의 같은 비교집단 내 상대 위치 변화를 사용한다.

`환산 유불리(%p) = 같은 비교집단에서의 총점 기준 상위 비율(%) - 같은 집단에서의 대학 환산 기준 상위 비율(%)`

예: 상위 2.35% → 상위 1.82%이면 +0.53%p다. 전체 응시자 누적을 조건부 대학 집단 누적에서 곧바로 빼지 않는다. 모집단·학년도·동점 정책·규칙·분포 버전이 맞지 않거나 자료가 없으면 판단 보류다. 프런트 예시는 서버 결과 형태의 가상 값을 표시하고 정합성만 검사한다. 실제 분포 생성·환산·유불리 계산은 서버 엔진이 담당한다.

가상 예시의 단순 부호 기준을 실제 유리·중립·불리의 운영 임계값으로 확정하지 않는다. 모형 오차와 비교 가능성을 반영하는 승인 기준이 별도로 필요하다.

## 권한과 다른 페이지

3페이지의 검색·결과·건수·상세 전체는 유료가입자 전용이다. 일반가입자에게는 유료 안내만 제공하고, 운영 API는 결과 조회 전에 활성 유료 권한을 검증한다. 검색 대상 자체는 유료 학생의 성적 또는 추천 목록으로 제한하지 않는다. 성적이 없으면 학생 분석 항목은 성적 입력 필요로 표시한다.

4페이지는 같은 분석 엔진 결과를 이용해 환산에 유리한 후보를 찾아주는 추천 화면이다. 기존 도전학교·핵심학교·여유 후보, 학과별 펼침, 2/3 기본 목록과 1/3 와일드카드를 유지한다. 2페이지 리포트는 선택한 모집단위를 정리하는 기존 목적을 유지한다.

## 검증

기존 유료 권한·직접 검색 검사를 포함해 23개 Node VM 기반 화면 이벤트·데이터 검증을 통과했다. 1페이지 데이터에 학생·자체누적·예측 필드가 없음을 확인했고, 3페이지는 같은 환산점수의 학과별 다른 지원 판단, 유리/도전 및 불리/여유 사례, 모집단·학년도·동점 기준 불일치 시 유불리 판단 보류를 검사했다. [검증 코드](verify.cjs)와 [검증 기록](verification.json). 실제 브라우저 시각 검수, 운영 API 권한 검사와 실자료 엔진 검증은 별도다.
