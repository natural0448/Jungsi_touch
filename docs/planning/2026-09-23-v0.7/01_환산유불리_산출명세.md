# 대학별 환산 유불리 산출 명세 v0.7

상태: 구현 설계 제안. 자체 통합·대학별 분포와 올해 입결 비교 모델은 승인 전이다. 공식 규칙 검증 및 모델 평가 없이 아래 식으로 운영 순위를 발행하지 않는다.

## 1. 세 가지 수치를 분리한다

1. 통합 누적: 국어·수학·탐구2 표준점수 합 T(x)의 전체 유효 응시자 기준 위치. 문·이과를 나누지 않는다. 후보 탐색의 출발점이다.
2. 대학 환산 유불리: 같은 비교집단에서 대학 방식 적용 전후에 학생의 상대 위치가 얼마나 달라지는가. 서로 다른 만점의 점수 자체를 비교하지 않는다.
3. 과거 입결 대비 위치: 특정 모집단위·전형·군의 합격권 또는 상위70% 기준과 비교했을 때 어느 쪽에 놓이는가. 올해 합격확률과 구별한다.

환산에 유리한 대학에서도 희망 학과의 과거 기준에 못 미칠 수 있다. 반대로 환산상 이득이 작더라도 과거 기준을 충족하는 학과가 있을 수 있다. 유불리와 입결 도달을 하나의 임의 종합점수로 합치지 않는다.

## 2. 입력과 공식 환산

학생 성적 x에는 시험 학년도, 국어·수학 선택과목 및 표준점수·백분위·등급, 탐구2 과목 및 점수, 영어·한국사 등급 등 실제 대학 규칙이 요구하는 값이 있어야 한다. 표준점수 합 400이라는 값만으로 대학 환산을 하지 않는다.

모집행 o의 규칙 r로 S_o(x;r)를 계산한다. 영역별 표준점수/백분위/변환표준점수, 반영비율, 탐구 선택 방식, 가산점, 영어·한국사, 반올림·절사·최고점 제한을 해당 학년도 공식 자료에 따라 적용한다. 수능 외 요소가 필요한 전형은 수능 부분점수와 전형 총점을 구분한다.

학년도·실제 모집단위·전형·모집군 PK에 규칙 버전을 연결한다. 대학 하나에 단일 규칙을 붙이지 않는다. 같은 대학·같은 규칙의 모집행을 화면에서 묶을 수는 있다. 기존 모집표에 캠퍼스ID나 계산식 열을 임의로 추가하지 않고, 이미 검수 중인 모집행 키를 참조하는 별도 규칙·산출 구조로 설계한다. 캠퍼스 표시는 원문에서 확인된 식별 내용으로 유지한다.

## 3. 비슷한 후보군 만들기

이 단계의 ‘비슷함’은 확정 대학 서열이 아니다. 학생의 전공·지역 등 희망 조건과 비교 가능한 과거 입결의 통합 누적 구간을 바탕으로 대학·모집단위 후보를 묶는 방향을 제안한다. 구간 폭·거리·전공 간 비교 정책은 아직 미정이다.

과거 결과가 대학 환산 누적이라면 학생의 전체 총점 누적과 의미가 다르다. 같은 명칭의 %만으로 직접 연결하지 않는다. 검증된 척도 연결 또는 넓은 초기 범위를 사용하고, 척도 미일치로 후보를 확정 탈락시키지 않는다.

탐색 이후 모집단위별로 환산하여 재정렬한다. 초기 통합 누적 범위 밖에도 환산에 유리한 후보가 있을 수 있어 범위 확대 경로를 유지한다. 특수계열은 별도 탐색 후 같은 자격·환산·입결 검증을 적용한다.

## 4. 환산 유불리의 제안 지표

비교 가능한 모집행 묶음 C에 대해 동일한 참조 표본/가중 분포 P_C를 사용한다. 각 참조 응시자의 성적 조합 z를 모든 대상 규칙에 실제로 대입할 수 있어야 한다. 연도·분모·표본 가중치·동점 정책이 같아야 한다.

p_base,C(x) = P_C(T(z) >= T(x))
p_o,C(x) = P_C(S_o(z) >= S_o(x))
advantage_pp(x,o,C) = 100 * (p_base,C(x) - p_o,C(x))

내부 p 단위는 0~1이다. advantage_pp의 단위는 퍼센트포인트다. 양수이면 대학 환산에서 상대 위치가 개선된다. 예: 같은 비교집단 기준 상위2.35% → 상위1.82%이면 0.53%p 개선이다. 이 예시는 가상이다.

핵심 조건:

- 대학별 유효 모집단·응시 가능 과목이 다르면 학교별 누적을 그대로 같은 분모라고 취급하지 않는다.
- 비교 가능한 공통 P_C를 구성한 경우 총점 기준 p_base도 그 P_C에서 다시 계산한다. 페이지 상단의 전체 응시자 누적을 조건부 집단의 대학 누적에서 빼지 않는다.
- P_C가 전체 응시집단과 같을 때만 상단 전체 누적을 baseline으로 재사용할 수 있다.
- 서로 다른 P_C 묶음 사이에는 통합 유불리 순위를 매기지 않는다. 사용자에게 비교집단 범위를 설명한다.
- 대상 학생이 해당 모집행 점수 산출 조건을 충족해야 한다. 지원 자격 검증은 별도 상태로 유지한다.
- 동점 포함/제외 정책을 맞추고 수치 반올림 전에 순위를 계산한다. 모델 오차가 순위 차이보다 크면 순위를 공동 구간으로 제시하거나 보류한다.

단순한 ‘환산점수/만점’, 서로 다른 대학의 원점수 차이, 서로 다른 업체·연도·분모의 누적 평균은 유불리 지표로 사용하지 않는다. 표본이 없거나 기준을 맞출 수 없다면 수치 유불리·가장 유리한 대학 순위는 null로 두고 공식 반영 규칙과 확인된 계산 결과만 제공한다.

대학별 유불리에 쓰는 상대 위치는 참조 분포에서의 위치다. 해당 대학의 실제 지원자 중 등수나 진학사 모의지원자 중 등수로 표시하지 않는다.

## 5. 추천 이유의 근거

계산 이력에서 국어·수학·탐구·영어/한국사·가산점·반올림의 적용값과 공식 근거 위치를 남긴다. ‘수학45% 반영’은 규칙 설명이고, ‘수학 때문에 유리’는 비교 근거가 필요한 추가 주장이다.

정량 기여도를 제시하려면 비교집단 내 대조 성적 프로필 또는 명시한 반사실 기준과 기여 계산 방법을 검증한다. 비선형 탐구선택·가산점·절사 효과가 있으면 임의로 더해 %p 원인을 나누지 않는다. 인과 기여 근거가 없으면 확인된 규칙과 학생의 과목 강점을 나란히 설명하고 확정적인 기여 수치는 생략한다.

## 6. 학과별 과거 입결 비교

합격권과 상위70%는 각각 source_metric_id와 결과 학년도를 유지한다. 수능 표준점수 합, 대학 환산점수, 백분위 평균, 최종등록자 70% 값, 업체 추정 합격권은 서로 바꾸어 쓰지 않는다. 정의가 확인되지 않은 ‘합격권’을 실제 최종 합격자 최저점으로 이름 바꾸지 않는다.

직접 점수 비교는 같은 의미·같은 척도로 연결됐을 때만 한다. 현재 환산점수에서 과거 다른 반영식의 점수를 곧바로 빼지 않는다. 반영식이 같더라도 시험 난도·점수 분포가 달라 학년도 간 척도 연결이 별도로 필요할 수 있다.

과거 총 환산점수만으로 올해 환산점수를 역산하지 않는다. 원 성적 조합을 확보했거나 검증된 변환·분포 연결 방법이 있을 때만 bridge_version_id와 오차를 기록해 비교한다. 이 조건이 없으면 과거 원자료는 열람 가능하되 개인 도달 판정은 ‘비교 보류’다.

비교 가능한 상위 비율로 연결한 경우 margin_pp = 100 * (historical_cut_fraction - personal_converted_fraction). 양수/0이면 해당 과거 기준 이상, 음수이면 해당 과거 기준 미만이다. 이 값도 같거나 검증된 연결 척도에서만 계산한다. 비교기준이 다른 학과 간 margin을 무조건 하나의 순위로 합치지 않는다.

학과 범위는 실제 행 목록과 개수로 표현한다. ‘2개 과거 기준 이상 / 3개 비교 가능 / 1개 비교 보류’처럼 분모를 보존한다. 비교 불가를 기준 미달로 세지 않는다. 학과를 고정 서열로 두고 그 이하 학과 모두를 충족했다고 간주하지 않는다.

4개년 상세는 각 연도의 원문과 매핑을 별도로 유지한다. 학교 묶음의 2024~2027 모집표 독립 전사·양방향 대조·행 보충·PK 연결이 완료되지 않았으면 검수 완료 상태를 부여하지 않는다. 4개년 요강 확보와 4개년 입시결과 확보도 별개다.

## 7. 지원 자격과 와일드카드

eligibility: eligible / needs_confirmation / ineligible.

성적 조건, 선택과목, 해당 전형의 거주·학교 이수 등 자격과 면접·실기 등 비수능 요소를 공식 자료로 확인한다. 누락 정보는 needs_confirmation이다. ineligible은 추천 목록에서 제외한다. needs_confirmation은 추가 확인 영역으로 두며 ‘지원 가능’이나 자동등록 가능이라고 표시하지 않는다.

와일드카드 카테고리 nursing / health / education은 운영자가 공식 학과 설명으로 검수한 태그다. 키워드 일치만으로 자격 경로나 계열을 확정하지 않는다. 중복 후보는 동일 모집행 키로 하나의 관심 항목만 저장한다.

## 8. 권한·산출 이력·오류 처리

모든 실제 계산과 정렬은 애플리케이션 계층에서 수행한다. 서버는 유료 권한과 리포트 소유자를 검사하고 승인된 결과만 전달한다. 브라우저에는 핵심 원자료·전체 분포·규칙 테이블을 보내지 않는다. 프레젠테이션의 가상 계산은 시연에 한정한다.

산출마다 input_version, ruleset_version, population_id, model_version, tie_policy, candidate_set_version, historical_result_id, bridge_version, generated_at을 보존한다. 관심 목록은 리포트 간에 같은 PK를 참조하되 성적/규칙 변경 시 재계산 상태를 표시한다.

결측값과 미승인은 null+reason으로 반환한다. 모델 미승인, 공식 규칙 미확인, 지원자격 확인 필요, 연도 척도 미일치, 입결 자료 없음, 수능 외 요소 미확인을 구분한다.

## 9. 구현 시 필수 검증

- 같은 총점이어도 성적 구성에 따라 대학 유불리가 달라질 수 있음.
- 동일 양의 선형 점수척도 변환은 참조분포 순위를 바꾸지 않음.
- 만점이 큰 대학을 우선하는 정렬이 없음.
- 모집단·학년도·동점 정책 불일치에서는 유불리 비교를 거절.
- 과거 다른 반영식/척도·불확실한 연결에서는 도달 판정을 보류.
- 비교 보류를 기준 미달/0으로 세지 않음.
- 같은 대학의 반영식이 다른 모집행을 분리.
- 지원자격 미충족을 추천하지 않음. 특수계열에도 같은 검사 적용.
- 회원 권한과 리포트 소유권을 서버에서 검사.
- 관심 목록에 같은 모집행 중복이 없음. 진학사에 자동 전송 없음.

이번 단계는 위 검증의 인수 조건을 정의한 것이다. 실제 공식 대학 규칙과 결합 분포 엔진 검증을 완료했다고 의미하지 않는다.
