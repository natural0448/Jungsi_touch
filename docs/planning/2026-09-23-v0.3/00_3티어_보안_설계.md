# Jungsi_touch v0.3 — 3티어와 외부 반출 억제 설계

작성일: 2026-09-23  
상태: 아키텍처·협업 명세 초안. 운영 시스템 보안이 구현·검증된 상태는 아님.

## 확정한 요구와 적용 범위

- 주 사용자는 학생·학부모, 부 사용자는 교사·입시담당자다.
- 첫 화면은 개인 성적 없이 대학 정시 자료를 조회한다. 실제 수능 입력 후 대학별 환산·후보 비교로 이어진다.
- 데이터와 핵심 계산 로직의 외부 반출을 줄이는 것을 우선 설계 조건으로 둔다.
- 사용자는 3티어 구성을 검토하고, .env를 이용한 내부 협업과 프레젠테이션 레이어 중심 설계를 요청했다.
- 추가 답변에 따라 **모든 공동 제작자는 전체 코드·데이터에 접근**하는 신뢰 집단이다. 공동 제작자를 화면 전용 권한으로 제한하는 안은 채택하지 않는다.
- 기술 스택·클라우드·첫 적용 학년도·대학 범위·이용자 로그인 정책은 아직 미정이다.

이 문서는 [v0.2 기획](../2026-09-23-v0.2/00_기획_안내.md)에 보안 경계와 협업 방식을 추가한다. 기존 분석·추정 모델의 검증 조건과 삭제 금지 원칙은 유지한다.

## 1. 3티어가 하는 일과 남는 한계

3티어는 화면, 업무 처리, 데이터 저장의 책임을 나누는 구조다. 폴더를 세 개 만드는 것만으로 보안이 생기지는 않는다. 실제 실행 위치, 네트워크 접근, 사용자 권한, 응답 데이터 범위와 배포 산출물까지 분리해야 한다.

| 접근 주체 | 접근할 수 있는 것 | 보호 목표와 한계 |
|---|---|---|
| 일반 이용자·외부 접속자 | 브라우저 코드, 화면 값, 자기 요청에 허용된 API 응답 | 핵심 엔진·전체 누적표·비밀값·다른 이용자의 정보에 직접 접근하지 못하게 함 |
| 공동 제작자 | 사용자 결정에 따라 전체 코드·데이터 | 열람 가능한 자료의 복제 자체를 기술적으로 완전 차단할 수 없음 |
| 서버 프로세스 | 자기 작업에 필요한 데이터·비밀값 | 외부 요청이 서버의 높은 권한을 우회 사용하지 않게 통제 |

브라우저에 전달한 정보는 저장·복사·재수집될 수 있다. 코드 난독화, 우클릭 방지, 비밀 URL, 소스맵 비공개는 핵심 보안 경계를 대신하지 못한다. 공개한 대학 자료를 전부 열람할 수 있다면 여러 요청을 통한 재구성 가능성도 남는다.

자체 비공개 누적분포·가중 성적 조합·모델 보정 계수와 실행 구현은 서버에 두고 요청 결과만 제공한다. 이미 대학이 공개한 공식 환산 규칙 자체를 우리만 아는 비밀로 간주하지 않는다.

## 2. 제안하는 실행 구조

~~~mermaid
flowchart TB
  subgraph T1["1. 프레젠테이션 — 이용자 브라우저"]
    UI["자료 검색 · 성적 입력 · 후보 비교"]
    CLIENT["API 클라이언트 · 표시 형식 변환"]
    UI --> CLIENT
  end
  subgraph T2["2. 애플리케이션 — 서버"]
    API["HTTPS API · 세션·권한 검사 · 요청량 통제"]
    ENGINE["대학별 환산 · 누적 조회 · 공개 응답 구성"]
    API --> ENGINE
  end
  subgraph T3["3. 데이터 — 비공개 저장소"]
    SERVE["검수된 조회 자료 · 배포 누적표"]
    RAW["원본 · 가중 성적 조합 · 모델 자료"]
    PERSONAL["성적·결과 저장소 — 보관 정책 확정 시"]
  end
  CLIENT -->|"필요한 조건·성적만 요청"| API
  ENGINE --> SERVE
  ENGINE --> PERSONAL
  JOB["내부 데이터 생성·검수 작업"] --> RAW
  JOB --> SERVE
~~~

내부 생성·검수 작업은 2티어의 별도 실행 작업이며 서비스의 네 번째 필수 티어를 의미하지 않는다. 조회 API 프로세스는 운영에 필요한 배포 자료를 읽고 원본·모델 학습 자산 전체를 읽는 권한은 필요할 때만 갖는다. 사람인 공동 제작자의 전체 접근과 프로세스의 최소 권한은 별개다.

첫 구현은 하나의 API 애플리케이션 안에서 환산·분포·응답 모듈을 나누는 방식으로 시작할 수 있다. 3티어가 서버 3대나 복잡한 마이크로서비스를 반드시 요구하지는 않는다. 운영에서는 데이터 저장소의 공개 접속을 막고 API에서만 필요한 자격으로 접근하게 한다. 팀원의 관리 접근은 개인 계정과 별도 관리 경로로 허용한다.

## 3. 각 티어의 책임

| 티어 | 포함 | 외부 브라우저로 보내지 않을 항목 |
|---|---|---|
| 프레젠테이션 | 검색·필터, 폼, 입력 형식 검사, 목록·비교, API 호출, 비율을 %로 표시 | DB 접속값, 서버 공통 비밀키, 전체 점수–누적표, 자체 모델·환산 엔진 코드 |
| 애플리케이션 | 인증/세션과 인가, 입력·학년도·지원조건 검증, 계산, 동점·버전 처리, 응답 허용 필드 선택 | SQL·스택 추적, 원본 경로, 비밀 환경변수, 대량 내부 자료, 자체 모델 파라미터 |
| 데이터 | 공식 원본, 정제·검수 자료, 규칙 버전, 배포 누적표, 모델 근거, 선택적 개인 성적 보관 | 공개 DB 포트·버킷·백업 링크, 공개 디렉터리의 CSV/XLSX/JSON 덤프 |

서버 렌더링을 채택하더라도 이름이 ‘프론트엔드 프로젝트’라는 이유로 서버 비밀이 자동 보호되지는 않는다. 렌더된 HTML, 초기 상태 JSON, 응답, 캐시, 로그로 보낸 값은 노출될 수 있다. 서버 렌더링·BFF를 둔다면 해당 실행 코드는 보안 관점에서 2티어로 분류한다.

## 4. API로 허용할 정보

- 대학 자료 조회: 공개를 승인한 모집행·입시결과·출처·기준일.
- 성적 비교: 요청한 성적 1개와 선택한 모집행에 대한 환산 결과·누적 위치·비교집단·공개 배포 버전.
- 근거 보기: 공개 모집요강과 해당 개인 결과의 공식 영역별 반영 설명.
- 내부 관리: 원본·전체 분포·검수·배포는 별도 관리 API와 내부 권한으로 처리. 일반 서비스 응답에 포함하지 않음.

결과를 설명하기 위해 공개 규칙과 모델의 대상·한계를 알려 주되, 전체 분포표나 모델 생성 코드를 함께 전달할 필요는 없다. 내부 버전 조합과 공개 배포 식별자를 서버에서 연결해 재현성과 제한된 응답을 함께 확보한다.

## 5. 반복 조회를 통한 수집·추론 억제

표 전체를 내려주지 않아도 점수를 조금씩 바꿔 반복 질의하면 분포나 계산 동작을 일부 추정할 수 있다. 따라서 서버 비공개만으로 ‘복원 불가능’을 약속하지 않는다.

- 한 요청은 성적 한 사례와 제한된 수의 후보로 구성한다.
- 서버가 계정/세션·기관·IP·작업 비용에 따른 요청 한도와 시간당·일별 사용량을 적용한다. 수치는 실제 교사·학생 사용량을 확인한 뒤 정한다.
- 연속 점수 스캔, 과도한 후보 순회, 비정상 병렬 요청을 관찰해 지연·추가 확인·일시 제한으로 대응한다.
- 교사 상담처럼 정당한 다수 학생 이용은 별도 사용 범위로 설계한다. 모든 다중 사례를 공격으로 처리하지 않는다.
- 공개 조회는 페이지 단위로 제공하고 전체 내부 자료를 반환하는 편의 API를 만들지 않는다.
- 정밀도는 통계적 근거와 사용 목적에 맞춘다. 단순 반올림이나 오류를 섞는 방법으로 모델 보호를 대신하지 않는다.
- CORS는 브라우저의 출처 정책을 보완한다. 비브라우저 호출자의 접근을 차단하는 인증 수단은 아니다.

OWASP는 API 접근권한을 각 요청에서 확인하도록 권고하고, 과도한 자동화 이용은 업무 흐름별 위험과 기술적 제한을 함께 설계하도록 설명한다. [Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html), [REST Security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html), [API6:2023](https://api-security.owasp.org/editions/2023/en/0xa6-unrestricted-access-to-sensitive-business-flows/)

## 6. 공동 제작과 배포 경계

모든 공동 제작자가 접근하는 비공개 코드 저장소를 기본안으로 한다. 저장소 개수는 보안의 핵심 조건이 아니며, 현재 팀의 전체 공유 방침에서는 모노레포도 적절하다.

~~~text
apps/web/           화면, 상태, API 클라이언트, 가상 응답
services/api/       권한 검사, 입력 검증, 공개 응답 변환
packages/engine/    대학 환산·누적 엔진 — 서버에서만 참조
packages/contracts/공개 API 스키마·타입 — 비밀 코드 의존 금지
~~~

원본·대용량 데이터·모델 자산은 팀 전원이 접근하는 비공개 저장소에 두고 출처·해시·버전으로 연결할 수 있다. 전체 공유를 위해 모든 자료를 프론트엔드 빌드에 포함하거나 Git에 넣을 필요는 없다.

현재 프로젝트의 Resource·outputs에는 원본·분석 자료가 있으므로 프로젝트 루트 전체를 웹 공개 디렉터리로 배포하지 않는다. 웹 배포는 필요한 산출물만 선택하고 서버 패키지·자료·환경변수 파일의 포함 여부를 검사한다. 기존 파일의 이동·삭제·저장소 권한 변경은 이번 작업에서 수행하지 않는다.
