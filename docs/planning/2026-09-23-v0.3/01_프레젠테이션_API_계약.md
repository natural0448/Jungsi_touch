# 프레젠테이션 중심 설계와 API 계약 v0.3

작성일: 2026-09-23 · [3티어 설계](00_3티어_보안_설계.md)

모든 공동 제작자는 전체 코드·데이터에 접근한다. 프레젠테이션 중심이라는 말은 화면 개발을 API 계약과 가상 응답으로 먼저 진행한다는 뜻이다. 팀원에게 핵심 엔진을 숨기는 권한 정책을 의미하지 않는다.

## 1. 화면 내부의 역할

| 구성 | 역할 | 경계 |
|---|---|---|
| 페이지·컴포넌트 | 대학 자료, 입력 폼, 비교표, 출처 상세 | 결과 표시와 사용자 상호작용 |
| 폼·화면 상태 | 선택 후보, 입력 임시값, 로딩·오류·자료 상태 | 브라우저 상태를 서버의 권한 판정 근거로 신뢰하지 않음 |
| API 어댑터 | 요청 형식 구성, 세션과 API 통신, 오류 처리 | 운영 비밀키를 포함하지 않음 |
| 표시용 변환 | 날짜·소수점 형식, 0~1 비율을 %로 표시 | 대학별 환산·누적 보간·자체 모델 계산을 수행하지 않음 |

서버 검증은 폼 검사와 별도로 시행한다. 숨겨진 버튼·비활성화된 메뉴·클라이언트 역할값만으로 기능 권한을 통제하지 않는다. 프로덕션에서 임의 mock 모드나 관리자 모드를 켜는 서버 우회 설정을 두지 않는다.

## 2. 화면과 데이터 흐름

### U00 — 첫 자료 화면

개인 성적 없이 학년도·지역·대학·전형·모집군으로 공개 승인된 자료를 찾는다. 서버는 필요한 모집행과 공개 입시결과만 페이지 단위로 반환한다. 로그인 없이 조회할지 여부는 별도 정책으로 남긴다.

자료가 없을 때는 미공개·미수집·검수 중·해당 없음의 뜻을 유지한다. 대학 자료 조회를 위해 개인 성적을 요구하지 않는다.

### U05 — 실제 수능 입력

시험 학년도와 과목·점수 종류를 입력한다. 입력은 기본적으로 화면 메모리에 두는 안을 제안한다. 서버 성적 보관, 자동 임시 저장, 공유 여부는 별도로 결정한다.

성적값은 URL·분석 이벤트·오류 로그에 넣지 않는다. POST 본문으로 전송해도 서버·프록시·관측 도구가 본문을 기록하면 남을 수 있으므로 해당 경로의 본문 기록과 마스킹 정책을 함께 설정한다.

### U04 — 후보 비교

한 성적 사례와 선택한 후보를 서버로 보낸다. 서버가 유효성·접근권한·사용량을 확인하고 계산한다. 프론트엔드는 결과를 표시하며 누적표나 계산 코드를 다운로드하지 않는다.

환산점수와 누적비율을 따로 보여 준다. 모델 미검증·분포 없음·범위 밖이면 그 이유를 표시하고 임의의 0%로 대체하지 않는다. 미검증 모델이 확정 누적값으로 보이는 표시도 허용하지 않는다.

### 근거 보기

공식 반영 규칙, 해당 결과의 영역별 기여, 자료 기준일, 비교집단, 모델 한계, 공개 배포 식별자를 보여 준다. 자체 모델의 전체 가중치·배포 테이블·원본 저장 경로는 포함하지 않는다. 공표된 대학 환산식은 공개 출처로 설명할 수 있다.

## 3. 공개 응답의 최소 계약

[기계 판독용 계약 초안](handoff/presentation-contract.json)은 프레젠테이션에서 사용할 키의 허용 목록을 정리한 문서다. 실행 중인 API나 완성된 OpenAPI 검증기를 의미하지 않는다.

| 경로 제안 | 입력 | 반환 | 서버 처리 |
|---|---|---|---|
| GET /api/v1/admissions | 학년도·조건·페이지 커서 | 공개 승인된 모집행·지표·출처·다음 커서 | 공개 범위 확인, 필터 검증, 페이지 크기 제한 |
| POST /api/v1/score-comparisons | 실제 수능 성적 1개, 후보 식별자 목록 | 후보별 환산점수·누적 위치·상태·공개 배포 식별자 | 세션/권한·입력·지원 조건·배포 상태·요청 비용 검사 |
| 관리 API — 별도 계약 | 팀 계정으로 승인된 작업 | 원본·검수·분포·배포 자료 | 일반 이용자 접근 거부, 개인 계정별 기록 |

공개 조회의 로그인 여부와 계산 시 익명 세션·회원 로그인 중 어느 방식을 쓸지는 아직 정하지 않았다. API 경로가 공개돼 있는 것과 데이터가 누구에게나 허용되는 것은 다르다. 선택한 정책에 따라 서버가 각 요청을 검사한다. 브라우저에 공통 서비스 API 비밀키를 심는 방식은 사용하지 않는다.

결과 저장·다중 학생·기관 관리 API는 보관·권한 정책을 정한 뒤 추가한다. 저장 기능을 채택하면 매 조회에서 소유자나 허용된 상담 관계를 확인한다. ID를 추측하기 어렵게 만드는 것만으로 접근을 허용하지 않는다.

## 4. 응답 필드와 미산출 상태

| 필드 | 목적 |
|---|---|
| data_kind | published 또는 synthetic. 가상 자료의 운영 혼입 방지 |
| academic_year | 적용 학년도 |
| public_release_id | 서버 내부 규칙·모델·자료 버전 조합과 연결되는 공개 배포 ID |
| offering_id | 결과 대상 모집행. ID 자체는 권한 증명이 아님 |
| converted_score / score_maximum | 서버가 계산한 점수와 해당 만점 |
| percentile.ratio_gt / ratio_ge | 0~1 엄격 상위·동점 포함 비율. 화면에서 %로 표현 |
| percentile.status | estimated / unavailable |
| percentile.unavailable_reason | model_unvalidated / out_of_range / population_undefined / missing_distribution 등 |
| percentile.population_label | 비교집단의 설명 |
| percentile.estimate_notice | 추정·예시 여부와 필요한 한계 |
| source_label | 공개할 출처 설명 |

산출 불가인 점수·비율은 null과 사유를 함께 반환한다. 동점 구간과 모델 불확실성 범위는 같은 의미로 사용하지 않는다. 수치 정책은 v0.2의 정의를 따른다.

request_id는 문제 추적용 식별자이며 인증 수단이 아니다. 응답에는 학생 이름이나 입력 성적 전체를 불필요하게 반복하지 않는다. API 에러에는 안전한 코드·설명·추적 ID만 넣고 SQL·환경변수·스택은 반환하지 않는다.

## 5. 팀의 화면 개발 흐름

1. 팀원이 공유한 계약·.env 예시를 읽는다.
2. 가상 응답으로 자료 검색·입력·비교의 정상 및 오류 상태를 만든다.
3. API 담당자가 같은 계약으로 서버를 구현한다.
4. 개인별 개발 접속 정보로 실제 개발 API와 연결한다. 운영 성적·비밀값을 가상 데이터에 복사하지 않는다.
5. 같은 UI에서 mock 어댑터를 API 어댑터로 교체한다. mock 결과를 만드는 과정에 실제 엔진을 프론트엔드 의존성으로 추가하지 않는다.
6. 실제 공개 전에 응답·번들·캐시·로그와 접근권한을 검증한다.

handoff의 모든 대학명·점수·누적비율은 화면 개발용 합성 예시다. 특정 학년도를 출시 범위로 확정하거나 실제 대학의 결과로 사용할 수 없다. 가상 API의 응답을 고정한 것은 화면 상태 확인 목적이며 실제 계산 기능을 구현한 것이 아니다.

## 6. 구현 후 완료 조건

- 브라우저 JS·HTML·초기 상태 JSON·소스맵·정적 파일에 엔진 코드, 전체 분포, 실제 비밀값이 없다.
- 프론트엔드는 공개 계약의 필드만 받고 내부 ORM 객체나 저장 레코드 전체를 받지 않는다.
- 비로그인/세션 만료·권한 없음·요청 한도·미산출 상태가 화면에서 구분된다.
- 브라우저 검증을 우회한 입력도 서버에서 검증한다.
- 다른 사람의 저장 결과 ID와 관리 API에 접근하는 시도가 거절된다.
- 개인 성적·결과는 공유 캐시에 저장하지 않고, 브라우저 영구 보관 여부를 명시적 정책으로 처리한다.
- 원본·기존 버전은 보존하며 배포는 허용 목록에 포함된 파일만 사용한다.

현재는 이 완료 조건을 정한 단계다. 운영 보안 시험이나 침투 테스트를 통과했다는 의미는 아니다.
