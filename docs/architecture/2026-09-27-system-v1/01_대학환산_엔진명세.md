# 대학별 정시 환산 엔진 — 구현 계약 v1

작성: 2026-09-27. 상태: 구현 명세와 가상 계약 예제. 실제 대학의 운영 규칙을 구현·승인한 문서가 아니다.

[통합 설계](00_시스템_통합설계.md) · [구현 순서와 검증](02_구현순서_검증기준.md)

## 1. 설계 결정

**공통 계산 엔진 + 버전이 있는 대학 규칙 + 공식 조회표 + 모집행 연결**로 구현한다. 대학마다 독립된 프로그램을 복제하지 않는다. 공통 연산으로 표현할 수 없는 예외만 코드 검토와 독립 검증을 거친 확장 함수로 추가한다.

환산 엔진의 업무는 대학이 정한 점수를 정확히 계산하는 것이다. 전국 누적, 대학별 분포 추정, 예상 컷, 추천·실시간 집계는 이 점수를 사용하는 별도 모듈이다. 대학 반영비율은 대학 공식 계산에만 적용하며, 합의된 전체 총점 정의를 바꾸지 않는다.

```text
calculate_conversion(
    profile_version,
    academic_year,
    offering_pk,
    release_id,
) -> ConversionResult
```

서비스 계층이 승인된 규칙과 표를 가져오고, 순수 계산 함수는 받은 입력만으로 항상 같은 값을 돌려준다. 계산 중 웹에서 최신 표를 임의로 읽거나 현재 날짜에 따라 규칙을 바꾸지 않는다.

## 2. 규칙의 적용 단위

`학년도 + 기존 실제 모집행 PK + service_release`에서 적용할 규칙 버전을 정확히 하나로 결정한다. 기존 실제 모집행은 대학·캠퍼스·모집단위·전형·모집군을 식별한다. 대학 이름만으로 산식을 결정하지 않는다.

- 같은 산식을 공유하는 모집행은 하나의 `rule_version_id`를 참조한다.
- 같은 대학에서도 계열·전형별 반영식이 다르면 별도 연결이다.
- 학생별로 유리한 두 산식 중 높은 값을 쓰는 공식 규칙은 한 규칙 안에 대안 분기와 최댓값 선택을 명시한다. 중복된 활성 연결로 표현하지 않는다.
- 같은 모집행에 두 활성 규칙이 겹치거나 적용 조건이 불명확하면 오류다. 우연히 먼저 읽힌 규칙을 사용하지 않는다.
- 2024·2025·2026·2027은 각각의 공식 규칙과 변경 이력을 유지한다. 최신 연도 규칙으로 과거 입결을 재계산했다고 표시하지 않는다.
- 현행 매핑 엑셀의 PK와 캠퍼스 식별을 존중한다. 규칙·조회표·산출 결과는 별도 구조로 만들고 기존 모집표에 산식 열을 추가하지 않는다.

## 3. 입력 계약

| 구분 | 필요한 값 | 처리 |
|---|---|---|
| 시험 식별 | 수능 적용 학년도, 실제 수능 여부 | 모의고사와 혼합하지 않음 |
| 국어·수학 | 선택과목, 표준점수, 백분위, 등급 | 대학이 실제 사용하는 항목을 요구하고 공식 연도별 허용 조합 확인 |
| 탐구 | 과목별 코드·영역·표준점수·백분위·등급 | 과목 동일성·응시 조합·반영 개수 검사 |
| 영어·한국사 | 등급 | 총점 누적에는 넣지 않지만 규칙이 요구하면 환산 필수 |
| 기타 공식 조건 | 제2외국어/한문 대체 등 규칙이 요구하는 성적 | 해당 규칙에만 조건부 입력, 없는 점수를 임의 대체하지 않음 |
| 지원 자격 | 전형이 요구하는 지역·학교 이수 등 확인 사실 | 점수 입력과 별도 상태. 모르면 확인 필요 |
| 추적 | 학생 ID, 성적 버전, 입력 확인 상태 | 공개 로그에는 성적표 원문·식별 정보를 노출하지 않음 |

첫 버전의 사용자 입력은 실제 성적표에 있는 값을 기준으로 한다. 표준점수만 보고 백분위·등급을 추측하지 않는다. 공식 대응표로 결정 가능한 경우에만 해당 표 버전을 남기고 보완한다. 전형 총점에 학생부·면접이 필요한데 자료가 없다면 대학 **수능 부분점수**까지만 산출한다.

프로필 수정은 새 버전이다. 이전 요청의 느린 계산 결과가 최신 프로필 결과를 덮어쓰지 않도록 `profile_version`과 `release_id`를 확인하고 채택한다.

| 묶음 | 필드 예시 | 이유 |
|---|---|---|
| 식별 | contract_version, rule_id, rule_version_id, academic_year | 코드/자료/연도별 재현 |
| 상태 | data_kind, approval_state, reviewed_by, reviewed_at | 가상·추정·공식 검수 구분 |
| 근거 | source_document_id, URL, 원문 해시, 페이지·표·주석, 공시일 | 산식과 각 파라미터를 공식 근거로 추적 |
| 적용 | 별도 offering_rule_bindings | 실제 모집행과 재사용 산식을 연결 |

| 자격 | eligibility_conditions, non_csat_components | 산출 가능과 지원 가능 구분 |
| 조회표 | conversion_table_refs | 탐구 변환점수·영어/한국사 등급점수·영역 최고점 등 |
| 연산 | typed operation DAG | 계산 순서·분기·가산·상한·절사 위치 명시 |
| 출력 | output_node, score_scope, score_unit, official_precision | 수능 부분/전형 총점·표시·순위 기준 |
| 검증 | official_examples, boundary_cases, validation_record | 독립 정답과 일치 여부 |
| 호환 | engine_contract_version, extension_versions | 엔진 변경 시 이전 결과 재현 |

모집요강의 수능 100% 같은 요약 비율만으로 수식이 완성되지는 않는다. 예를 들어 탐구 변환표준점수의 학년도, 표 조회 기준이 백분위인지, 과탐 가산이 과목별인지 합산 후인지, 마지막 절사가 어디에 적용되는지가 모두 필요하다.

## 5. 연산 그래프와 공식 순서

고정된 한 줄 공식이나 모든 대학에 공통인 가산 순서를 강제하지 않는다. 규칙마다 의존 순서가 있는 연산 그래프(DAG)를 선언한다. 입력·노드·표의 타입을 사전에 검사하고 허용한 연산만 실행한다.

| 연산 | 용도 | 반드시 정할 것 |
|---|---|---|
| input | 성적표 값 읽기 | 과목·필드·필수/조건부 |
| lookup | 등급점수·변환표 조회 | 표 버전, 과목 구분, 정확한 키, 결측 처리 |
| select_subjects | 반영 가능 과목 선택 | 허용 과목, 실제 성적 확인 |
| top_n | 상위 1/2개 등 선택 | 선택에 쓰는 값, 가산 전후, 동점 선택 규칙 |
| sum / average | 탐구 합산·평균 | 분모, 없는 과목 처리 금지 |
| weighted_sum | 대학 반영비율 적용 | 정밀한 계수, 입력 척도·분모 |
| multiply / divide / add / subtract | 스케일·기본점수·가산·감점 | 분모 0 차단, 적용 대상, 점수 단위 |
| conditional | 선택과목·계열 조건 분기 | 참/거짓/미확인 경로 |
| min / max / cap | 유리한 산식 선택·상한 적용 | 공식 허용 범위와 단계 |
| quantize / truncate | 반올림·절사 | 자릿수·방식·노드 위치 |
| approved_extension | 공통 연산 밖의 공식 예외 | 검토된 함수 ID·버전·독립 검산 |

엔진은 `eval`, 임의 Python/JavaScript 문자열 실행, 원본 엑셀 매크로 실행을 하지 않는다. 추출한 수식 문자열은 검토 자료다. 검토된 연산 계약으로 정규화한 뒤 실행한다.

어떤 대학이 탐구 가산 후 유리한 과목을 고르는지, 선택한 과목에만 가산하는지는 공식 근거에 따라 달라질 수 있다. 반영 비율·상위 과목 선택·영어 감점·절사 순서를 규칙의 데이터로 표현해야 한다.

## 6. 수치 정밀도

모든 계수·점수 상수는 정수 또는 10진 문자열로 저장한다. 이진 부동소수점으로 환산 점수를 계산하지 않는다. Python의 Decimal은 정밀도와 반올림 방식을 제어할 수 있지만 나눗셈이나 컨텍스트 정밀도에 의해 중간 반올림이 생길 수 있다. [Python Decimal 공식 문서](https://docs.python.org/3/library/decimal.html)

권장 구현은 유한 소수·비율을 가능한 한 정확한 유리수로 유지하고, 대학이 지정한 반올림·절사 노드에서만 지정 규칙을 적용하는 방식이다. Decimal을 사용하는 노드는 입력 범위에 따른 충분한 정밀도와 비정확 연산 감지, 더 높은 정밀도와의 대조가 필요하다.

- 기본 ROUND_HALF_UP을 모든 대학에 강제로 적용하지 않는다. 공식 규칙이 불명확하면 검수 대기다.
- 실제 공식 점수 산출을 위한 반올림과 화면 표시용 반올림은 다르다. 화면 자릿수로 등수를 재계산하지 않는다.
- 점수 상한도 공식 노드가 있을 때만 적용한다. 가산점 때문에 일반적인 만점을 넘는 경우를 임의로 잘라내지 않는다.
- Redis 순위 인덱스에는 공식 점수의 확정 최소 단위로 정수화한 값을 쓰는 안을 검토한다. 값이 정확히 표현되는 범위를 검증하고, 불명확한 소수 자릿수를 임의로 잘라 넣지 않는다. 공식 정밀도를 정수 점수로 안전하게 보존할 수 없으면 DB 등 정확한 비교 경로를 유지한다.
- 기존 전체 누적 모듈의 출력 반올림 정책을 대학 산식 정책으로 가져오지 않는다.

## 7. 결과 계약

```json
{
  "academic_year": 2027,
  "offering_pk": "SYNTHETIC-OFFERING-A",
  "profile_version": "SYNTHETIC-PROFILE-A-v1",
  "release_id": "SYNTHETIC-RELEASE-v1",
  "calculation_status": "calculated",
  "eligibility_status": "needs_confirmation",
  "score_scope": "csat_component",
  "converted_score": "634.00",
  "score_unit": "points",
  "official_max_score": null,
  "rule_version_id": "SYNTHETIC-CONVERSION-v1",
  "conversion_table_version_ids": ["SYNTHETIC-EN-v1", "SYNTHETIC-HI-v1"],
  "curve_status": "unavailable",
  "college_percentile": null,
  "reason_codes": ["SYNTHETIC_NOT_FOR_PRODUCTION", "CURVE_NOT_APPROVED"],
  "public_explanation": ["산식 계약 설명을 위한 가상 점수입니다."],
  "trace_ref": "internal-only"
}
```

위 객체는 내부 계약 설명용 가상 예시다. 공개 API는 `trace_ref` 등 내부 필드를 제거하고 현재 회원 권한에 맞는 결과만 반환한다. 실제 운영에서 가상 규칙은 호출할 수 없다.

`calculation_status`: calculated / partial / blocked / not_applicable.

`eligibility_status`: eligible / needs_confirmation / ineligible. 지원 자격이 미확인이라도 숫자 계산 자체가 가능할 수 있으므로 별도 상태로 둔다. 미확인·미충족 학생을 지원 가능 후보로 확정하지 않는다.

`curve_status`와 `forecast_status`도 환산 계산 성공 여부와 별도다. 점수는 계산됐지만 누적표가 없거나 올해 예상 컷이 미승인일 수 있다.

| 사유 | 동작 |
|---|---|
| RULE_NOT_FOUND / RULE_BINDING_AMBIGUOUS | 점수 null, 해당 모집행 환산 보류 |
| RULE_NOT_APPROVED | 운영 계산 차단 |
| CONVERSION_TABLE_PENDING | 올해 공식 변환표 대기, 작년 표 자동 대체 금지 |
| REQUIRED_INPUT_MISSING / INVALID_SCORE_COMBINATION | 누락 필드·오류를 반환, 0으로 계산하지 않음 |
| DOMAIN_NOT_VERIFIED | 해당 학년도·선택과목 점수 검증 보류 |
| NON_CSAT_COMPONENT_MISSING | 수능 부분점수는 가능, 전형 총점은 null |
| POPULATION_MISMATCH / CURVE_NOT_APPROVED | 환산점수 유지 가능, 대학 누적·유불리 수치는 보류 |
| YEAR_BRIDGE_UNAVAILABLE | 과거 원자료 조회 가능, 개인 도달 판정은 보류 |
| UNSUPPORTED_OPERATOR / ROUNDING_UNSPECIFIED | 규칙 구현·원문 확인 필요 |

각 노드의 사용 입력, 선택 과목, 조회표 값, 가산·감점, 반올림 전후 값, 공식 근거를 내부 계산 이력에 남긴다. 이용자 설명은 필요한 항목만 요약한다. 대학 공식 규칙 설명과 자체 추정 모형의 비공개 파라미터를 구분한다.

## 8. 대학별 누적 엔진에 연결

학생 점수 `S_o(x)`와 같은 규칙으로 정의된 대학 환산 분포 `G_o,y`가 있어야 상위 누적을 계산할 수 있다.

`p_o(x) = Pr_Z[S_o(Z) ≥ S_o(x)]`

여기서 Z의 학년도, 모집단, 성적 구성, 가중치, 동점 기준, 추정 방식은 분포 버전에 포함된다. 영어나 한국사를 사용하는 대학 분포를 만들 때는 참조 자료에 해당 성적의 분포·결합 관계가 필요한지 확인한다. 없으면 검증된 보완 모형과 불확실성을 남기거나 산출을 보류한다.

세 정시 자료는 역할별로 사용한다. 정시 S파일의 표본·동점자 평균·대학 환산 근거, 중등진학의 총점별 구성·누적 근거, 고속성장의 누적/대학 환산 표를 연도·모집단별로 정렬한다. 서로 다른 연도나 문/이과 조건부 누적을 전국 통합 누적인 것처럼 단순 평균하지 않는다.

- 직접 사용할 수 있는 대학 환산 분포는 척도·공식 산식·모집단 호환을 검증하고 자체 보정한다.
- 전체 총점 표만 있는 대학은 같은 총점의 여러 과목 조합을 표현할 보완 분포가 필요하다. 평균 조합 하나를 모든 학생으로 확장하지 않는다.
- 참고자료를 이용해 직접 보정한 곡선과 합성 성적 조합에서 계산한 곡선은 제작 방법을 구분한다.
- 과목별 주변분포만으로 결합분포는 유일하게 정해지지 않는다. 허용 가능한 여러 결합 가정에 대한 민감도와 참고자료 적합도를 평가한다.
- 실제 관측치와 추정치를 구분하고, 모형 차이보다 작은 대학 간 유불리를 확정 순위로 제시하지 않는다.
- 총점별 누적은 점수가 높을수록 같거나 작아야 한다. 대학 환산 누적도 같은 방향성과 0~100 범위, 분모·동점 규칙을 검증한다.

구체적인 총점 곡선 제작 방향은 [자체곡선 설계](../../implementation/2026-09-27_세참고자료_기반_자체누적곡선_설계.md)를 따른다.

## 9. 공식 규칙 구축·공개 절차

1. 한 학교의 2024~2027 원문 요강을 한 묶음으로 확보·검수한다. 학교 통합 전후 코드와 캠퍼스를 함께 확인한다. 모집표 독립 전사와 현재 데이터의 양방향 차이를 대조한다.
2. 검수된 실제 모집행마다 산식 적용 범위를 확인한다. 현재 데이터의 수능 비율·국수영탐 반영·탐구 개수·등급점수·가산점 열은 초안 근거로 활용한다. 값이 들어 있다는 이유로 공식 검증 완료로 처리하지 않는다.
3. 원문 공식·주석·변환표를 별도 규칙 패키지로 전사한다. 출처가 다른 구성요소는 각자의 근거를 남긴다. 변환표 미공개 상태를 보존한다.
4. 공통 연산으로 정규화하고 적용 PK, 표 참조, 의존 순서, 차원·단위를 정적 검증한다.
5. 공식 예제 또는 독립적으로 계산한 정답과 대조한다. 업체 엑셀·상담 결과는 교차 확인용이며 최종 공식 근거를 대신하지 않는다.
6. 동일 학교의 연도별 산식·모집행 변경을 검토하고, 영향받는 결과와 분포의 재계산 범위를 확인한다.
7. 규칙 검수와 운영 공개를 분리한다. 공개할 버전 묶음을 검증해 새로운 `service_release`에 포함한다. 공개 중인 과거 규칙은 수정하지 않고 새 버전을 만든다.
8. 새 점수·분포·추천·순위 인덱스를 준비한 뒤 공개 참조를 전환한다. 이전 공개 버전과 리포트는 재현 가능하게 보존한다.

제안 상태: draft → source_verified → calculation_verified → published. 각 단계의 검수 근거가 없으면 다음 단계로 표시하지 않는다. 모든 규칙의 상세 조건을 채웠다고 원문 모집표 전수 대조까지 완료한 것은 아니다.

## 10. 필요한 검증

| 검증 | 실패를 잡는 사례 |
|---|---|
| 독립 정답 대조 | 공식 예제와 소수 마지막 자리까지 불일치 |
| 같은 총점·다른 구성 | 전체 누적은 같지만 대학 환산이 달라져야 하는 학생 |
| 과목·등급 경계 | 탐구 선택 수, 선택과목 가산, 영어 등급 구간 |
| 선택과 가산의 순서 | 먼저 고른 뒤 가산하는 것과 가산 후 고르는 것의 차이 |
| 단계별 반올림 | 최종에만 반올림해 공식 예제와 달라지는 경우 |
| 부분점수 | 면접이 없는데 전형 총점을 완성한 것으로 표시하는 오류 |
| 규칙·표 버전 | 작년 변환표, 다른 계열 규칙, 겹치는 PK 연결 |
| 미확인 처리 | null을 0으로 바꿔 더 낮은 실제 점수를 만드는 오류 |
| 유불리 척도 | 대학 만점이 큰 것만으로 추천 순위가 올라가는 오류 |
| 모집단 일치 | 전체 누적에서 조건부 집단 누적을 무조건 빼는 오류 |
| 재현·재계산 | 같은 버전의 결과가 바뀌거나 오래된 작업이 최신 결과를 덮는 오류 |
| 공개 제한 | 가상·미검수 규칙이 운영 결과에 들어가는 오류 |

공식 자료에 예제가 없으면 테스트 정답을 같은 엔진으로 생성해 그 엔진의 정확성을 주장하지 않는다. 원문에 근거한 독립 수계산과 검토 기록이 필요하다. 공식적인 동점자 선발 기준은 별도 조건이며, 서비스 표시의 동일 환산점수 공동 순위를 실제 최종 선발 순위로 바꾸어 말하지 않는다.

## 11. 가상 계약 예제

[가상 규칙 패키지](examples/synthetic_rule_pack.json), [가상 입력·기대 결과](examples/synthetic_contract_cases.json)를 제공한다. 대학 규칙 데이터의 모양과 계산 흐름을 검토하기 위한 예시다. 실제 대학의 반영비율·점수·합격 결과가 아니며 운영 공개를 금지한다.

예시 산식:

`((국어표준 × 0.30) + (수학표준 × 0.40) + ((탐구1표준 + 탐구2표준) × 0.30)) × 5 + 영어조정 + 한국사조정`

| 가상 학생 | 국어 | 수학 | 탐1 | 탐2 | 국수탐2 총점 | 영어 | 한국사 | 가상 대학 점수 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A | 126 | 128 | 63 | 65 | 382 | 2등급 | 1등급 | 634.00 |
| B | 130 | 124 | 63 | 65 | 382 | 2등급 | 1등급 | 632.00 |
| C | 126 | 128 | 63 | 65 | 382 | 3등급 | 1등급 | 630.00 |

이 예제는 같은 총점 학생의 대학 점수가 달라지는 환산 계약을 설명한다. 전국 학생의 과목 간 결합분포나 자체 누적곡선을 추정한 예제가 아니다. ROUND_HALF_UP도 이 가상 규칙에만 지정한 것으로 실제 모든 대학의 규칙이 아니다.

[설계 검증 기록](design_verification.json)은 문서 링크, 가상 규칙 표시, 연산 참조와 예제 산술의 검증 결과다. 운영 환산 엔진 실행, 실제 대학 공식 검증, 생산용 JSON 스키마 검증 또는 전체 연산 검증을 뜻하지 않는다.
