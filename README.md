Supabase Auth + PostgreSQL을 사용하는 현재 3티어 구조는 구현 가능하다. 실제 서비스 운영은 production_ready=false / NOT_READY다. 최소 설정 조회 200은 실제 로그인·DB·권한·입시모델 인수가 아니다. [Supabase 운영 인수인계](docs/current/Supabase_운영_인수인계.md)의 SUP-01~11·입력·의존관계·완료조건을 따른다. 연결안/단일authority는미선택이며실DB/Bearer로그인/유료권한/승인자료/22API/외부4페이지는NOT_RUN/HOLD다.

현재 문서는 공통 명세에서 생성하고 Git 인덱스 또는 커밋을 기준으로 일치 여부와 계층·데이터 제외를 검사한다. 검산은 선택한 Git 스냅샷만 새 outputs 폴더에 복사해 실행한다. 실제 데이터가 필요한 로컬 테스트를 커밋 검산에 섞지 않는다.

GitHub는 현재 비공개 저장소의 브랜치 보호 기능에 HTTP 403과 요금제 업그레이드 요구를 반환했다. 로컬 훅과 자동 검사는 설정하되 원격 병합을 강제 제한하는 보호가 활성화된 상태로 표시하지 않는다. 훅 적용 방법과 이후 main 반영 흐름은 개발 브랜치 운영 문서를 따른다.

1. **데이터 기반:** 대학·캠퍼스·모집단위·전형·학년도별 자료와 원문 출처를 정리합니다.

성적 분석이나 합격 가능성 예측은 아직 확정된 기능이 아닙니다. 예측 기능을 선택할 경우 필요한 데이터, 검증 방식, 결과의 의미를 별도로 설계합니다.

## 설계 시 지킬 데이터 기준

- **학년도 구분:** 전형이 적용되는 학년도, 입시결과의 대상 학년도, 시험 시행 연도, 문서 공표 연도를 별도 의미로 관리합니다.
- **출처 추적:** 핵심 데이터는 원문 문서와 해당 페이지·표·행 등을 찾을 수 있도록 연결합니다.
- **원본 보존:** 제공된 원본은 보존하고, 정제·변환 결과는 별도 파일이나 버전으로 생성합니다.
- **의미 보존:** 원점수·표준점수·백분위·등급·대학별 환산점수를 구분합니다. 미확인·미공개·해당 없음·실제 0을 혼동하지 않습니다.
- **비교 기준:** 입시결과의 지표명, 대상 집단, 만점, 산출 기준을 함께 관리하고 서로 다른 기준의 값을 동일한 지표로 합치지 않습니다.
- **변경 이력:** 모집단위 명칭, 모집인원, 환산표, 반영 규칙이 바뀌면 이전 근거를 보존하고 적용 시점을 기록합니다.
- **검증 상태:** 초안·원문 대조 완료·검토 필요 등 상태를 구분하며, 예시 데이터는 실제 입시 데이터와 명확히 구별합니다.

이 기준을 검토하는 공식 참고 자료로, 대입정보포털은 학년도별 전형 평가기준에 전년도 결과가 포함된다고 안내합니다. 따라서 기준 학년도와 결과 학년도를 따로 저장하는 설계를 제안합니다. [어디가 전형 평가기준 및 전년도 결과공개](https://www.adiga.kr/uct/acd/ade/criteriaAndResultView.do?menuId=P)

대학별 산출 방식이 다르면 입시결과의 직접 비교가 어렵다는 안내도 확인했습니다. 점수 체계와 지표 정의를 함께 보존하는 설계의 참고 근거입니다. [어디가 아주대학교 2026학년도 공개 자료](https://www.adiga.kr/ucp/uvt/uni/univDetailSelection.do?menuId=PCUVTINF2000&searchSyr=2026&unvCd=0000146)

## 성적 조합·과목 분포를 반영하는 분석 보완 — v2 (2026-09-27)

## 과목 간 결합분포 요구 정정 (2026-09-27)

수학의 특정 점수를 받은 학생들의 국어·탐구 성적은 여러 점수로 퍼진다. 이 조합별 인원을 유지해 총점 분포를 만들어야 하며, 과목별 반영비율을 바꿔 해결할 문제가 아니다. 전체 총점은 합의한 국어·수학·탐구2 표준점수 합을 그대로 유지한다.

[joint_distribution.py](src/jungsi_touch/joint_distribution.py)는 연결된 네 성적 조합별 인원을 그대로 합쳐 기존 총점 누적 엔진에 전달한다. 공개 과목별 분포를 일대일 매칭하거나 임의 독립 결합하지 않는다. 고정 수학 점수 안의 국어 점수 분산, 같은 주변분포/다른 조합의 총점 누적 차이 등을 새 테스트 13개로 확인했고 전체 71개가 통과했다.

현재 구현은 이미 주어진 조합별 인원의 집계다. 공개 주변분포에서 실제 전국 결합분포를 추정·검증하는 단계는 별도로 필요하며 완료로 표시하지 않는다. 위 v2 가중합 예제는 이 요구의 해결안에서 제외하고 이력으로 보존한다. [정정한 수식·근거·구현 범위](docs/implementation/2026-09-27_과목간_결합분포_정정.md).

## GitHub 연결과 코드·데이터 관리 (2026-10-03)

저장소: [natural0448/Jungsi_touch](https://github.com/natural0448/Jungsi_touch). 원격 이름은 `origin`, 기본 브랜치는 `main`이다. 원격의 기존 초기 커밋과 README 이력을 유지한다. 에듀터치 내부 서비스의 정시터치 구현 자료 저장소로 사용한다.

Git에는 공통 계산 코드(`src/`), 공유 가능한 기획·화면·계약, 명확한 합성 예시, 데이터가 포함되지 않은 테스트와 검토한 공통 실행 도구를 올린다. 실제 성적·입결·모집표·환산표·누적곡선·모델 파일은 로컬 또는 비공개 데이터 저장소에서 별도로 관리한다.

`.env` 계열은 예시 파일까지 모두 제외한다. `Resource/`, `data/`, `datas/`, `outputs/`는 모든 깊이와 대소문자 조합에서 제외한다. `DATA_ACTIVE*.json`과 실제 모집행 연결 예시도 제외한다. 데이터 계층을 다른 이름으로 옮기거나 실제 데이터를 코드에 하드코딩해 제외 규칙을 우회하지 않는다.

기존 `scripts/`에는 실제 모집인원·모집행·매핑 자료와 이전 데이터 패치가 포함되어 있어 기본적으로 로컬 전용으로 둔다. 확인한 공통 CLI·합성 시연 도구 7개만 `.gitignore`에 명시하여 공유한다. 원자료 분석·학생 상담 문서와 실제 자료를 쓰는 통합 테스트도 로컬에 유지한다. 새 실행 도구는 실제 값과 비밀값 포함 여부를 확인한 뒤 개별 공유 대상으로 추가한다.

이전 기획 문서의 `.env.example` 예외는 현재 정책이 아니다. 공유 문서가 제외 자료를 참조하더라도 그 실제 자료는 GitHub에 포함되지 않는다. 비공개 자료에 의존하는 전체 통합 검증은 자료가 있는 내부 환경에서 수행한다.

변경을 올릴 때에는 `git status --short`로 대상을 확인하고, `git add .` 이후 `git diff --cached --name-only`로 실제 커밋 목록을 다시 확인한다. 보호 대상은 `git add -f`로 추가하지 않는다. 이후 `git commit`과 `git push`로 코드를 동기화한다. 원본·이전 버전·제외 자료는 삭제하지 않는다.
